# 分镜资产自动绑定技术设计

## 1. 确认范围与文档地位

用户已回复“1”确认：新生成分镜使用结构化资产 ID 自动绑定；旧镜头自由文本只产生候选，由用户预览确认后追加，不新增付费模型调用；写入具备权限校验、整批原子性及严格状态幂等。

行为与验收源是 `openspec/changes/storyboard-asset-auto-binding/specs/storyboard-asset-binding/spec.md`，`docs/openspec/changes/storyboard-asset-auto-binding/` 为 Comet 逐字镜像。本文件是已确认的实施设计，不表示功能已实现或测试已通过。开案 `design.md` 保留决策摘要并指向本文件；历史取舍保留在 brainstorm-summary。此次不改业务代码、数据、任务勾选、Comet guard/state 或 Git 提交。

不新增资产系统、别名字段、向量索引、幂等表、自动回填或自动媒体生成；不扩大工作区引用读模型，不改共享画布其他调用方。新生成仍只有原有生成请求；旧镜头预览与确认不创建模型任务。

## 3. 完整候选与两类证据

### 3.1 候选完整性及预算

前端复用 `listProjectAssetsPage`，每页不超过 80，遍历 hasMore，按资产 ID 去重，覆盖角色 character、场景 environment、道具 prop。资产无版本仍展示不可绑定原因。页请求失败、被取消或尚未完成时禁止声称“匹配完成”。分页展示不是并发快照；服务端预览和保存重新读取项目关联及候选，不信任前端拼出的全集。

模型上下文是完整目录的受限投影，仅含 assetId/category/name，不发送媒体正文。集中维护序列化 UTF-8 24 KiB 的摘要预算，同时服从上游完整 prompt 的上下文限制；字节数不等于 token 数。超额显示总数、发送数和缩减依据，只接受用户明确范围或已存在的章节结构化范围；仍超额则阻止生成，不能静默截前 60 或前一页。名称唯一性相对完整项目目录计算，不能因缩减隐藏同名。

项目模型没有 alias 字段，本版不建立别名索引，不从 definition 任意字段猜别名；spec 中“数据中已存在的别名”的条件在本项目不成立。名称仅去首尾空白，不做拼音、模糊、简繁或语义相似合并。

### 3.2 共用解析与旧文本发现的分工

共用解析接受显式 ID 或显式 category/name，返回资产身份、当前有效版本、证据类别、原文位置、可绑定性、缺图及问题。ID 非法、未知、跨项目、类别不符或超出该生成请求允许集合时拒绝，不回退名称；仅 ID 缺失时，结构化名称可在对应类型中唯一精确解析。

旧镜头另有无模型线索提取器，读取 description、当前 ShotRevision 的 plotDescription/action/dialogue/imagePrompt/videoPrompt 等正向文本。negativePrompt 不作正向依据。中文使用名称索引定位原文区间，不依赖英文 word boundary：

- 精确命中普通叙述只表示“提及”，作为未选中的候选展示；不把局部字符串命中提升为结构化身份证据。
- 对重叠的长短姓名、同名和无法分辨的边界报告歧义，不能把较长名字中的短名字自动绑定。否定、回忆、旁白或画外音保留原文警告，不声称规则能完整理解语义。
- “桑若视线落在领口……裴让停止喝粥……”展示桑若、裴让及各自原文，等待确认；不推断领口对应服装、喝粥对应碗勺，也不继承上一镜场景。
- “桑若：……”只证明说话人线索，不证明视觉在场；台词提到另一个姓名也不证明对方出镜。不复用 withShotDialogue 作为在场识别器，不扩展台词结构或改造配音。
- 只有明确的角色/场景/道具标签、有效结构化引用等视觉证据才进入明确匹配类；连续场景必须有可追溯的结构化证据。没有证据不自动复制上一镜引用。

身份唯一与视觉在场是两个独立结论。确定性解析可唯一找到候选，但普通文本仍必须由用户选择；前后端不能各维护一套更宽松的自动匹配规则。

## 4. 新生成数据流

1. 页面完整加载目录并展示摘要覆盖范围，提交章节生成任务及 projectId/unitId、用户选择范围。后端重校验项目与资产归属，并从真实目录构建摘要。
2. 后端将最终获准摘要与允许 ID 集合放入这一次已有任务的非敏感输入上下文，关联任务所有者、projectId/unitId 和章节生成 operation。provider 从同一份已校验输入构造实际 prompt；不能保存一套允许集合却向模型发送另一套。
3. 章节专用每行输出 `projectAssetRefs: [{ assetId, category }]`。模型不选择 assetVersionId，项目 assetId 不写入通用 assetBindings.nodeId。缺少 ID 的显式名称通过共用解析按完整目录判唯一，且解析出的 ID 仍必须属于该任务实际允许集合。
4. 前端保留 taskId，调用下节的生成解析操作。服务端按登录用户读取真实已完成任务、验证 project/unit/operation，解析其结果中的引用，再用当前有效版本和媒体指纹形成可保存结果；不接受客户端另传 allowedIds 作为授权凭据，不只比较客户端声明的摘要 hash。
5. 明确、有效、未超容量的引用自动纳入新镜头；歧义、缺版本或超容量问题必须先展示处理，不静默删项。缺图但版本有效可保存，明确没有可用参考图。
6. 前端把解析得到的 assetVersionIds 连同生成 taskId、行对应关系和解析基线交给既有 replaceProjectUnitShots 新生成保存链路。后端在保存事务中再次通过共用解析核对任务真实上下文、所选引用及当前版本，不信任中间解析响应的回传值。用户缩减选择只能取解析出的合法子集，另行人工绑定仍走原人工入口。
7. 现有替换能力仅用于用户明确发起的新分镜生成/替换流程，并保留 expectedShotIds 的并发保护；不能为了旧镜头补绑把旧章整章交给 replace。图像/视频从持久化的版本引用继续读取参考图，不从模型名称临时选图。

增加任务上下文字段使用已有任务记录，不增加业务表；只存 ID、类型、名称及范围信息，不持久密钥或敏感 URL。任务归属、当前项目关联和允许集合同时成立才接受模型引用，管理员权限也不能把跨项目 ID 变为本次生成合法引用。

## 5. API 合同与前端预览

以下为本次确定的新增接口设计，不是已存在接口声明。实际 HTTP 前缀 `/api` 由既有 http 配置提供。

| 操作 | 路径 | 输入与输出 |
| --- | --- | --- |
| 旧镜头只读预览 | `POST /api/projects/:id/units/:unitId/shot-asset-bindings/preview` | 输入目标 shotIds；输出逐镜完整已有引用、候选及证据、问题、剩余容量、服务端基线。 |
| 旧镜头整批追加 | `POST /api/projects/:id/units/:unitId/shot-asset-bindings/append` | 输入原基线和每镜选择的 assetVersionIds；输出 projectRevision、逐镜 addedCount/unchanged 与刷新数据。 |
| 新生成只读解析 | `POST /api/projects/:id/units/:unitId/shot-asset-bindings/resolve-generated` | 输入 taskId；读取真实任务输出，返回逐行解析引用、问题和保存校验所需基线，不创建镜头。 |

POST preview/resolve 是只读查询，不因 HTTP 方法创建任务、预览记录或幂等记录。预览最多接受 100 个去重后镜头，每镜确认最多提交 6 个不同版本；超出返回参数错误，UI 让用户明确缩小镜头范围，不隐式分批写入或只取前 100。资产候选本身没有 80 条总量上限。预览请求只传对象标识，基线由服务器读取真实记录生成。

确认按预览目标镜头全集回传 selection，未选择新增的镜头使用空数组；漏掉或多出基线镜头、重复冲突条目、缺字段都拒绝。用户明确改变目标镜头范围时重新预览。新生成保存继续使用既有接口，在章节生成适配中附带 taskId/行关联/解析基线，而非新建另一套整章写接口。

### 5.1 UI 行为

真实章节工作台新增“匹配镜头资产”，使用 AppDrawer 或 AppModal 产品容器及现有 token。逐镜显示已有绑定（只读）、建议、原文位置、证据等级、歧义、缺版本、缺图和总容量。默认只勾选明确有效且容量合法的视觉证据；普通中文叙述、姓名台词、画外音等一律不默认选中。整组超限不任意挑前几项，由用户选择。

无有效版本不可选；有有效版本无图可选但持续标记缺图。已有 5 个引用加 2 个建议显示总量 7、剩余 1，不能移除旧引用腾位。确认前说明“仅实增镜头的相关产物将过期并取消选中，历史内容保留”。取消预览零写入。

预览请求支持 AbortSignal；关闭界面可以取消未完成的只读请求。确认进行中禁用重复点击，但服务端幂等不能依赖按钮。确认请求断连不等于事务回滚，恢复后用同一原基线和原选择重试，不自动生成新基线掩盖结果。冲突后旧预览不可再次确认，重新预览并由用户复核；不得自动重放旧选择。成功后刷新对应项目/unit 的 Query 缓存，不跨用户 scope 复用。

## 6. 基线、集合与信任边界

### 6.1 服务端生成的完整基线

基线使用规范化对象和稳定排序，不依赖显示顺序；比较内容包括：

- projectId/unitId、目标 shotIds、项目辅助 revision；对象所有者与当前访问权限重新查询，不能从基线授权。
- 每镜 Shot 的稳定身份、所属项目/章节、标题、描述、时长、排序、状态、CurrentRevisionID，以及当前 ShotRevision 的完整脚本字段及内容摘要。只比 revision ID 会漏掉直接写字段。
- 每镜完整引用集合：referenceId、assetVersionId、role、status。去重只去完全相同的重复输入，不能按 versionId 抹掉 role/status 差异；已有行身份保留。
- 所有已有引用和预览可选版本的资产归属、项目关联、category、资产/版本状态、PrimaryVersionID、有效版本关系及 definition/prompt 等影响引用含义的内容。
- AssetRepresentation 的版本、role、mediaType、resourceId、metadata，原始参考图引用以及所用 Resource 的存在性、所有者和存储身份指纹。比较数据库里的媒体语义字段，不将临时签名下载 URL 当稳定指纹。
- 每镜历史产物的 ID/版本/内容指纹及 status/selected，便于计算既有失效策略对应的精确后置状态，防止重试时覆盖随后选择或新增的产物。

预览从数据库一致读事务读取目录与上述快照；不通过 SQLite 无匹配 UPDATE 获取写权限，保证预览零业务写入。PostgreSQL 使用一致读快照，SQLite 使用只读事务快照。匹配计算在读取快照后进行，返回结果可能立即变旧，确认必须重新检查。无需在预览阶段锁住用户思考时间。

### 6.2 本版不使用签名凭据

本次没有核验可复用签名密钥来源，故明确采用“客户端回传非信任乐观锁条件 + 事务内所有权/状态重校验”，不引入 HMAC 配置、临时 secret、签名表或伪装安全的普通 hash。基线最初由服务器产生，客户端按原样回传，但服务端不能证明客户端未篡改，也不宣称快照是审批或授权凭据。

服务端验证基线结构、对象 scope、完整集合与当前状态；选择对应的版本必须重新校验归属、状态、容量及允许的追加语义，基线绝不授权越权写入或跳过版本检查。恶意客户端可以自行提供与当前状态匹配的乐观锁条件，等价于重新读取后发起一个本就有权执行的追加；本版不保证其实际看过旧预览或遵守原预览时刻。严格并发和重复确认合同针对保持原基线、原 selection 的同一请求，不把 hash 当作防伪证据。后续若需要可审计的预览审批凭据，应另行核验稳定密钥来源再设计，不在本任务隐含承诺。

### 6.3 追加集合

令 B 为原引用全集，S 为服务端根据所选版本归一化得到的新增引用意图，D 为确需新增部分。现有唯一键为 `(shotId, assetVersionId, role)`，因此比较必须保留 role/status；新增 role/status 沿用项目视觉引用创建规则，由服务端生成，不由模型或前端指定。

同版本已存在时不借追加修改 role/status，也不添加另一个 role 来绕过容量；原引用如实保留并显示已有。S 对这些版本投影为 B 中原元组。仅不存在的版本生成默认引用元组，D 为这些元组。容量按已有与新增的不同 assetVersionId 计数，每镜不超过 6，与现有生成写路径及规范保持一致；完整并发快照仍保留每条 role/status 和行身份，同版本不同 role 的历史行不被折叠删掉。原数据的不同版本数已超上限时展示问题并拒绝本批次，不自动修复旧引用。

预期后置引用为 B ∪ D，原 referenceId 必须保持；新行 ID 是数据库生成身份，不要求客户端提前猜测，但其版本/role/status 及唯一性必须精确对应 D。所有未选中候选的快照也参与原预览校验，宁可要求刷新，不把变动目录继续显示为本次已核验状态。

## 7. 数据库协调与提交顺序

### 7.1 所有者域事务锁

采用相关资产拥有者域锁，不采用“先项目行锁、再找资产锁”或进程内锁。

- PostgreSQL：事务内 `pg_advisory_xact_lock`，逻辑 namespace 为 `storyboard-assets:<userID>`。将完整 namespaced key 以固定 SHA-256 派生为数据库 advisory lock 的有符号 64 位 key，编码集中维护，禁止使用进程随机 hash；碰撞只导致保守串行，不能跳过对象验证。按逻辑所有者 ID 稳定排序、去重后获取。
- SQLite：每个写事务在第一次事务读取前执行 `UPDATE assets SET id = id WHERE 1 = 0`，取得该文件数据库的写权限；机制仿照 `repository/upload_reservations.go:14-22`，不读写 upload 表，不修改资产行，不触发业务 revision。随后读取快照再写，避免 deferred read→write 升级窗口。
- SQLite 本身只有单写者，这不是应用新增的全局互斥服务；不把其他业务接入统一队列，不将 PostgreSQL 所有用户串行化。同一所有者的直接竞争操作可能互相等待，是为跨项目共享资产选择的保守粒度。
- 协调锁在所有相关入口任何对象行锁之前取得，持有到事务结束。之后按表的固定次序（项目、章节、镜头、项目资产关联、资产、版本、表现/资源、引用/产物）和各表主键稳定排序取得需要的行锁。不存在行的插入与关系删除也必须遵守协调协议，不能只靠现存行锁保护。

所有者集合从数据库对象关系派生，包括目标项目所有者、已有/所选资产所有者及关联资源所有者；管理员也取被操作对象的所有者，不取管理员 ID 代替。权限校验回答“能否操作”，锁域回答“谁与谁竞争”，两者不能混用。

锁外只做必要的对象 scope/所有者发现和初步鉴权；锁后重新读取并确认所有者集合、项目关联及权限。发现新的所有者不在已锁集合时回滚本事务，重新发现并按完整排序取锁，不能持有部分行锁后再补更早顺序的协调锁。共享资产的版本、媒体或删除操作必须覆盖所有关联项目；项目关联的增删也按同一协议修改，使关联全集复查可靠。无法稳定确定集合返回冲突，不循环持锁猜测。

### 7.2 直接竞争入口清单

仅改与本能力实际共享数据的写入口及其 repository 事务，不全仓加锁：

1. 镜头脚本/当前 revision、标题描述等直接字段更新；引用新增、删除及 role/status 更新。
2. 新分镜 replace、镜头/章节删除等会替换目标集合的操作。
3. 项目资产关联/解除关联，资产分类和身份变更；解除关联的引用检查与实际删除合在一个事务，不能检查后释放锁再删。
4. 资产有效版本切换、版本状态/内容更新及删除；原始参考图、表现资源和媒体落库，包括异步生成产物被正式采纳时的数据库写入。
5. 直接相关资源删除/清理/管理员删除的数据库阶段，及会改变本次产物后置状态的写入/选中操作。

共享资产变更在所有者协调锁下枚举并锁定所有关联项目，再执行既有需要的失效/revision 更新；不能只更新发起请求的那个项目。管理员权限不改变项目引用合法性。所有事务的锁顺序必须一致，不能在新接口加锁后假定旧写方天然安全。

project revision 仅作辅助冲突信号，不能代替完整快照。相关设置写入的旧 revision 绝对值回写改为事务内数据库递增或带原值条件的 CAS，不把旧内存对象的 revision 再写回；晚到写请求不能降低计数。无关项目业务不新增所有者协调锁，但不得保留会覆盖该项目 revision 的绝对回写漏洞。

### 7.3 确认事务算法

1. 验证请求格式、批次数量与必填 ID；登录和初步 scope 校验后发现所有者集合，开启事务，先获取协调锁，再获取必要行锁。
2. 在锁内重新鉴权并读所有对象。确认项目/unit/shot 对应、资产仍关联项目、版本有效、资源数据库状态与完整基线。任何跨项目或无权限对象立即失败，重试分支同样不能绕过。
3. 由原 B 和原 selection 计算 D、每镜容量、预期失效结果及 `expectedRevision = baselineRevision + (任一 D 非空 ? 1 : 0)`；不是用当前引用重新定义本次请求意图。
4. 当前状态精确等于原基线时进入首次分支。先完成全批验证，再仅对 D 非空镜头插入引用并执行既有 stale/selected=false 策略，保留历史记录/内容；不更新无增量镜头，不调用无条件 upsert helper。
5. 任一镜头实增时，在同一事务按 `WHERE revision = baselineRevision` 的 CAS 使用 `revision = revision + 1`，整批目标项目只增一次，不让引用 helper/失效 helper 再次自增。全批 D 为空时不写引用、不改产物、不改项目 revision。
6. 当前状态不等于原基线时，先判下节严格后置分支；不满足即整批冲突。所有插入、失效、CAS 必须一起提交或回滚，唯一约束冲突不能吞掉当部分成功。
7. 提交后返回逐镜实增/无变化结果并触发界面刷新。锁等待超时、SQLite busy、死锁受害事务等返回可重试错误；重试使用原请求且有界，不把新读快照偷偷替换原基线。

持锁段仅访问数据库，不调用模型、对象存储、HEAD 探测、网络图片读取或其他远程服务。媒体任务在远程阶段不持锁，只在正式数据库落库时参与协议。

### 7.4 严格后置状态幂等

只有所有目标镜头同时满足以下条件，才将同一原请求的重复确认返回为 unchanged：

- 权限、对象归属、项目资产关联、脚本及所有资产/版本/媒体指纹仍符合原请求。
- 当前完整引用恰好等于 B ∪ D：旧行身份和 role/status 不变，新元组恰好匹配，不允许额外新增、删除或同版本改 role/status。
- 项目 revision 恰好为上节 expectedRevision；无实增请求仍为原 revision。
- 原产物记录/内容保留，实增镜头的产物状态恰好符合一次既有失效的结果；无增量镜头产物不变，没有新增产物、重新选中等后续编辑。

该分支先于任何写入，不再次执行 stale、不更新 selected 或 revision。首次成功后另有脚本、引用、关联、版本、媒体或产物编辑，即使选定版本仍都在，也返回冲突；不以“已包含这些 ID”判断幂等。此为状态幂等，不证明历史上一定执行过这次请求；不存在请求审计或永久重放保证，也不新增幂等表。

## 8. 资源物理删除的真实边界

本次定向核验的四个文件是 `app/resource_delete.go`、`repository/resource_cleanup.go`、`repository/admin_storage_delete.go`、`app/resource_deletion_worker.go`。当前路径是业务/资源记录删除与 ResourceDeletionJob Outbox 同事务提交，worker 后续删除物理对象并重试；pending/processing 是删除任务状态，不能称为资源统一的 deleting 标记。清理及管理员路径有数据库引用复查，物理删除入口仍检查画布历史引用；这些不等于所有项目关联竞态已经被覆盖。

本设计沿用当前资源生命周期与 Outbox，不新造 deleting 状态或改成持锁远程删除。有关数据库删除与项目引用/媒体写入加入上节协调协议，锁内复查关联、版本、资源及相关引用。所有删除入口（含 purge/清空回收站）有业务引用时均拒绝；无引用且现有物理身份、变体及生产者结算证据完整时才允许进入删除流程。本次不恢复旧 purge 绕过引用的行为，也不把并行资源生命周期实现归为本次成果。

删除先提交时，追加不能把已经删除的资产/版本当有效对象；资源记录消失但版本仍有效时，原预览媒体指纹失效，确认冲突，刷新后按真实缺图状态显示。追加先提交时，删除必须在同协调协议下观察到新引用并拒绝，purge 也不例外。数据库锁不保证外部对象永久存在或可下载；外部对象消失时下游生成仍需报告真实媒体访问错误，不用“绑定成功”伪装可用参考图。

上线证据必须覆盖关联/媒体写入与数据库删除及 Outbox 的两种交错顺序；不把一个事务包住新追加接口视为竞态已解决。没有这些测试证据时，不宣称端到端资源删除安全。

worker 验收沿用当前能力：本地对象实际失败/重试；已入队远端作业因缺少合法结算证据时，真实 worker 在 HTTP DELETE 前拒绝、保留对象与记录并安排重试。远端 HTTP 失败到最终物理清理的完整闭环由已存在的 `add-remote-storage-physical-settlement` 后续变更验收，不是本次分镜绑定的交付条件；不伪造 settled proof，不以 HTTP helper 重试代替 worker 验收，也不据保护性拒绝宣称远端最终可删。

## 9. 错误、权限与容量裁决

所有对象归属校验在 app 业务入口与锁内重校验完成；前端隐藏按钮不是权限。整批包含一个非法对象即全批失败，不返回部分成功，也不向用户泄露其他账户对象标题或路径。

沿用 `{ code, data, msg, reason }`，失败使用真实非 2xx HTTP 状态和非零业务 code。下列 reason 是本功能计划新增的机器分类，实施时统一注册到既有错误合同和 OpenAPI，而非声明当前已存在：

| 情况 | HTTP / reason | 行为 |
| --- | --- | --- |
| 空 ID、基线结构错误、超批次上限、重复冲突项 | 400 / `storyboard_asset_binding_invalid_request` | 修正输入，无写入。 |
| 未登录或无权访问 | 既有 401/403/404 及鉴权 reason | 保持现有不泄露对象的策略，不能降级为默认用户。 |
| 版本无效、类别错误、生成引用不在真实允许集合或跨项目 | 422 / `storyboard_asset_binding_invalid_reference` | 拒绝，返回已授权范围内的问题；跨账户细节隐藏。 |
| 每镜总引用超过 6 | 422 / `storyboard_asset_binding_capacity_exceeded` | 显示已有/新增/剩余，要求重新选择，不截断。 |
| 脚本、引用、关联、版本、媒体或严格后置不符 | 409 / `storyboard_asset_binding_conflict` | 全批零提交，刷新预览，禁止后台自动套用新基线。 |
| 协调锁等待或数据库暂时繁忙 | 503 / `storyboard_asset_binding_busy` | 有界重试原请求，超时后明确提示。 |
| 内部数据库失败 | 既有 500 错误合同 | 全事务回滚，日志不得输出敏感资源 URL/密钥。 |

缺图是预览问题而非版本无效；允许有效版本缺图引用，但不发送不存在的参考图片。HTTP 成功不替代 code 检查；页面通过 ApiError.reason/code 处理，不解析 msg，不吞写入异常返回默认成功。

## 10. 验证策略与上线约束

以下是后续实施验收设计，不是本次已运行测试结果。

- **解析表驱动**：合法 ID、非法 ID 搭合法名称、跨项目/跨账户、完整目录同名、没有 alias、长短中文姓名、普通叙述/姓名台词/画外音/否定/回忆、negativePrompt、不推断碗勺服装、不继承场景；检查证据等级及默认勾选。
- **候选与请求捕获**：零引用章节、三类目录、超过 60、跨 80 分页、末页失败/取消；24 KiB 边界及多字节中文，上游实际 prompt 确有摘要；真实允许集合与 taskId/project/unit 绑定，伪造 allowedIds 或挪用另一任务拒绝；共享画布合同不变。
- **数据与权限**：缺版本不可选、缺图可选、已有 5+新增 2 拒绝；同版本多 role/status 保留，不用去重隐藏原行；混入非法镜头/版本整批回滚，原脚本、镜头 ID、旧引用和历史产物内容不变。
- **状态幂等**：首次实增项目 revision 只增一次、无变化零写入、两并发同确认一次实增一次 unchanged；首次成功后新增/删除其他引用、改 role/status、改脚本/媒体、重新选中产物、增加产物均冲突；改变 selection 不能冒充原请求重放。
- **基线信任**：非法结构/遗漏旧引用/伪造外部项目版本拒绝；回传 hash 不能替代重读；授权客户端自造当前匹配条件仅具普通追加能力，不把该结果解释成可信预览审批。
- **双数据库屏障**：文件型 SQLite 与 PostgreSQL 使用独立连接，必要时跨进程。控制“预览完成→竞争方进入→确认取锁/提交”交错，分别覆盖脚本、引用删除/role/status、整章 replace/delete、解除关联、版本切换、媒体写入和资源删除。验证旧入口先取协调锁、管理员按对象所有者、共享资产覆盖多项目、跨所有者排序无反向锁等待，迟到设置写回不降低 revision。
- **资源删除**：追加与解除关联/资源数据库删除/Outbox 两种提交顺序、共享物理对象、显式 purge 同样遵守引用保护、版本仍有效但图片消失、本地 worker 失败重试及已入队远端作业证据不足时的实际 worker 安全拒绝/保留/重试；数据库正确与外部文件可用分别断言，远端完整清理闭环保留给上述现有后续变更。
- **UI 与下游**：真实章节路由明暗主题、键盘、长列表滚动、取消零写入、超容量选择、冲突刷新、断连重试；捕获图像/视频上游 payload 证明实际使用正确版本参考图，不以独立 HTML 或静态截图代替。

采用范围内专项测试，不在文档任务中运行业务构建或启动服务。实施后同步 HTTP API/OpenAPI、功能概览、代码地图和 pending-test；无 schema 变化不改数据库文档。任一数据库环境未具备时如实记录未验证，不以 SQLite 单测推断 PostgreSQL advisory lock 已正确实现。

## 11. 风险、交付与回退

旧自由文本方案以明确确认换取低成本，不承诺完整语义识别。模型仍可能漏引用；非信任解析和问题展示比自动猜测优先。所有者域锁牺牲同一用户部分并发度，需以有限批次、短事务、固定锁序控制；SQLite 文件单写者限制不能通过宣称“用户锁”消除。无签名基线不提供预览来源防伪；严格快照只保护遵循协议的乐观并发。资源外部可用性不由数据库锁保证。

最关键风险是既有直接竞争写方漏接协议。上线前须用上节屏障测试证明每类入口，而不是凭锁 helper 的存在宣称多实例安全；超出直接关联范围的并发重构不混入本变更。现有工作区代码差异保留，不归因于本设计。

回退撤下新入口及章节专用适配，不删除合法引用、历史产物或已有任务，不把 stale 产物恢复成有效选中，不用整章替换回滚补绑。
