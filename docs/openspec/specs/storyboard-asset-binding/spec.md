# storyboard-asset-binding Specification

## Purpose
为项目章节分镜提供统一、可解释的角色、场景和道具资产绑定能力，使新生成镜头和既有镜头都能安全关联项目资产版本并供图像、视频生成使用，同时保护人工引用、脚本和历史产物，显式处理歧义、容量与并发冲突。

## Requirements

### Requirement: 项目候选发现独立于工作区引用
系统 SHALL 独立获取当前项目完整分页的角色、场景和道具候选，不依赖已有镜头引用，也不将工作区引用资产列表扩展为全项目资产列表；加载失败或未完成时 MUST 明示不完整状态，不以部分数据宣称匹配完成。

#### Scenario: 首次章节没有任何资产绑定
- **WHEN** 新章节尚无镜头引用，而项目已有角色、场景和道具资产
- **THEN** 生成与匹配均能发现三类候选，工作区原有引用资产读取行为不变

#### Scenario: 候选超过单页或加载中断
- **WHEN** 项目候选跨越多个分页，或任一分页请求失败
- **THEN** 系统持续加载直到完整，失败时提示重试且不将已加载部分视为完整匹配结果

### Requirement: 生成提示词包含有边界的真实资产上下文
系统 SHALL 将项目资产摘要实际编入章节生成提示词，摘要包含可引用的结构化资产标识、类型和名称。摘要 MUST 有明确预算；超预算时提示用户或按明确章节上下文缩减并披露范围，不静默截取固定数量，不影响其他共享画布调用方。

#### Scenario: 候选超过原固定数量或提示词预算
- **WHEN** 项目资产超过 60 项，或资产摘要超过预算
- **THEN** 系统不静默取前 60 项；显示完整或缩减后的覆盖范围，无法按明确上下文缩减时要求用户缩小范围后再生成

#### Scenario: 章节与共享画布分别生成
- **WHEN** 章节生成提交候选摘要，其他画布调用方未提交章节资产上下文
- **THEN** 前者的模型实际收到受限摘要，后者原有生成合同保持不变

### Requirement: 两个入口采用保守确定性匹配
系统 SHALL 为新分镜和旧镜头使用一致的匹配规则：优先有效结构化资产 ID，缺少 ID 时才使用保守的唯一精确名称或数据中已存在的别名。系统 MUST 拒绝非法、未知或跨项目 ID，不能用名称兜底绕过；任意子串和多义匹配不得自动绑定。

#### Scenario: 有效 ID 和唯一名称
- **WHEN** 镜头提供当前项目有效资产 ID，或未提供 ID 但名称在对应类型中唯一精确匹配
- **THEN** 系统提出对应资产版本引用并说明匹配依据

#### Scenario: 非法 ID 搭配合法名称
- **WHEN** 模型输出或用户提交包含非法、未知或跨项目 ID，同时名称对应当前项目资产
- **THEN** 系统拒绝该标识并报告原因，不以名称匹配绕过校验

#### Scenario: 同名未知名称和子串
- **WHEN** 名称对应多个候选、没有候选，或仅为另一名称的任意子串
- **THEN** 系统分别报告歧义或未匹配，不猜测、不自动创建资产，也不臆造别名

#### Scenario: 中文自由文本只产生待确认候选
- **WHEN** 旧镜头普通描述出现“桑若视线落在领口……裴让停止喝粥……”等中文姓名线索，而没有明确的结构化视觉引用
- **THEN** 系统展示姓名候选、原文依据及待确认状态，不默认勾选或自动绑定，不以英文单词边界漏掉中文线索，不因姓名子串或否定、回忆语境推断在场，也不由领口或喝粥推断服装、碗勺等道具

#### Scenario: 台词姓名与视觉在场分离
- **WHEN** 台词行首出现“桑若：”，或对白、旁白、画外音提及另一角色姓名
- **THEN** 系统仅将姓名作为说话人或提及线索展示，不据此默认视觉绑定；没有独立明确视觉证据时必须由用户预览选择确认

### Requirement: 镜头连续性必须有明确证据
系统 SHALL 仅在明确结构化证据支持时利用场景连续性；角色、场景和道具不得仅因上一镜已引用而被全部继承，没有明确证据的连续性推断 MUST 留待用户确认。

#### Scenario: 上一镜有引用但当前镜缺少明确线索
- **WHEN** 当前镜未提供角色或场景线索，也无结构化场景连续性依据
- **THEN** 系统不复制上一镜全部引用，对可能的连续场景标记待确认

### Requirement: 版本有效性缺图和容量显式处理
系统 SHALL 只绑定有效资产版本；无版本不可绑定，无图但有有效版本可以绑定并标记缺图。每镜已有与新增引用去重后的总数 MUST 不超过当前上限 6，超限时要求选择，不静默截断或删除已有引用。

#### Scenario: 无版本与无图分别呈现
- **WHEN** 候选中一个资产无有效版本，另一个有有效版本但无可用图片
- **THEN** 前者不可绑定并报告原因，后者允许版本引用但明确缺图，且不自动创建图片或媒体任务

#### Scenario: 已有引用占用容量
- **WHEN** 镜头已有 5 个引用，另有 2 个不同有效版本建议
- **THEN** 系统显示总量 7 和剩余容量 1，要求用户选择，保留已有 5 个引用而不静默取前一项

### Requirement: 新镜头绑定版本供下游参考
系统 SHALL 将已确认有效且容量合法的角色、场景和道具资产版本引用与新镜头共同持久化，使后续图像和视频生成使用这些版本的可用参考图；模型输出 MUST 作为非信任输入重新校验。

#### Scenario: 三类资产随首次分镜落库
- **WHEN** 首次章节生成输出当前项目角色、场景和道具，解析结果唯一且有效
- **THEN** 新镜头保存对应版本引用，图像及视频生成获得正确版本的参考图，缺图状态被显式保留

### Requirement: 旧镜头补绑必须预览确认且仅追加
系统 SHALL 提供旧镜头批量匹配预览，逐镜显示建议、理由、歧义、缺图、容量和失效影响，默认只选明确有效匹配。用户确认前 MUST 不写入；确认后只追加选定引用，保留镜头 ID、脚本、已有人工引用及历史产物记录，不整章替换或重新生成镜头。

#### Scenario: 多镜头确认和取消
- **WHEN** 用户为旧章多镜头查看预览后取消，或选择合法建议并确认
- **THEN** 取消不产生任何写入；确认仅追加选中引用，不改变镜头 ID、脚本、原引用和历史产物内容

#### Scenario: 旧镜头匹配不产生外部任务
- **WHEN** 用户执行预览或确认补绑
- **THEN** 系统只使用确定性本地或服务端规则，不调用付费模型、不创建外部模型任务，也不自动生成媒体

### Requirement: 批量追加具备事务权限与并发保护
系统 SHALL 对用户、项目、章节、每个镜头和资产版本的归属及可用性进行强校验，并对预览时脚本 revision、引用集合和版本状态进行并发校验。任一越权、失效或冲突 MUST 原子拒绝整个批次并要求刷新，不允许部分成功。

#### Scenario: 预览后脚本引用或版本改变
- **WHEN** 确认前脚本 revision、已有引用或选定版本状态发生不符合预览基线的变化
- **THEN** 系统拒绝整个批次，提示冲突并要求刷新预览，其他镜头也不写入

#### Scenario: 同版本引用角色或状态改变
- **WHEN** 预览后已有引用的 assetVersionId 不变，但 role 或 status 被其他操作修改
- **THEN** 系统将其视为完整引用集合冲突并原子拒绝整个批次，不能仅因版本 ID 相同或已包含选定 ID 而返回幂等成功

#### Scenario: 确认与解除项目资产关联并发
- **WHEN** 批量确认与相关资产解除项目关联并发执行
- **THEN** 两者在共同数据库协调协议下原子裁决；解除关联先提交时确认拒绝整个批次，确认先提交时解除关联必须复查新引用并按既有引用保护规则处理，不得在事务外检查后删除关联而留下本次新增的无效项目引用

#### Scenario: 确认与资源删除及 purge 并发
- **WHEN** 批量确认与资源删除或 purge/清空回收站并发执行
- **THEN** 两者遵守共同数据库协调协议及当前资源生命周期保护；删除先提交时确认按完整基线拒绝失效对象，确认先提交时所有删除入口均复查新增业务引用并拒绝，不恢复旧 purge 绕过引用行为；资源记录或外部对象意外消失时如实报告指纹冲突或缺图，不承诺物理对象永久可用

#### Scenario: 已入队远端删除缺少结算证据
- **WHEN** 实际删除 worker 处理已入队远端作业但缺少合法生产者结算证据
- **THEN** worker 在远端 DELETE 前安全拒绝，保留对象和记录并安排重试；本次验证该边界及本地 worker 的实际失败重试，不伪造结算证据，也不把 HTTP helper 重试当作 worker 清理闭环；完整远端结算与最终清理由已存在的远端物理结算后续变更验收

#### Scenario: 批次混入跨项目或越权对象
- **WHEN** 一个批次同时包含合法对象和无权限或跨项目的镜头、章节或资产版本
- **THEN** 服务端拒绝并回滚全部写入，不泄露无权限对象细节

### Requirement: 重复确认不重复失效
系统 SHALL 对引用去重，只在实际新增引用的镜头上执行既有失效语义：相关产物标记 stale、取消当前选中状态，但保留产物记录。相同确认在基线后置状态一致时 MUST 幂等成功，不重复失效、不额外推进业务 revision；无变化镜头不得受到影响。

#### Scenario: 首次追加与重复确认
- **WHEN** 用户成功追加引用后重复提交同一确认，且脚本、版本和引用集合符合该次确认的预期后置状态
- **THEN** 首次仅对实增镜头标记相关产物 stale 并取消选中，重复提交返回无变化且不再次修改产物或 revision

#### Scenario: 已有全部建议引用
- **WHEN** 当前镜头已经包含全部建议引用且并发基线有效
- **THEN** 系统报告无新增，不改变产物状态、选中状态或业务 revision
