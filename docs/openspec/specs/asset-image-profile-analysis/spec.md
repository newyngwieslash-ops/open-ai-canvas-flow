# asset-image-profile-analysis Specification

## Purpose
为项目角色、场景和道具提供从已保存参考图提取可见信息的结构化档案草稿，让用户逐字段审阅后安全采用；保持模型推断与资产事实分离，保护资源归属、既有档案、声音和版本历史。

2026-10-24用户批准范围收敛：核心分析、审阅、选择采用、CAS/恢复/授权、历史baseline与媒体身份合同不变。资源删除验收采用下述保守合同；完整生产者恢复、远端物理结算和旧数据维护迁至后续change，不以迁出宣称这些能力通过。范围及证据映射见[范围收敛记录](../../changes/archive/2026-10-26-add-asset-image-profile-analysis/.comet/scope-convergence.md)。

## Requirements

### Requirement: 分析来源与模型准入
系统 SHALL 从当前用户项目中目标资产的已保存参考图创建多模态文本分析任务，绑定资产、基准版本和具体来源资源；服务端 MUST 校验关联、归属、ready 图片状态及模型视觉输入能力，不信任客户端传入 URL 或能力声明。

#### Scenario: 合法参考图分析
- **WHEN** 用户选择拥有的角色资产参考图及支持图片输入的文本模型提交分析
- **THEN** 任务记录来源和基准版本，结果是该资产的草稿，不创建新资产或修改现有档案

#### Scenario: 伪造来源或缺少能力
- **WHEN** 请求伪造项目关联、他人资源、非基准参考图，或模型不支持图片及能力未知
- **THEN** 系统在上游调用前拒绝，不能退化为纯文本分析或泄露资源信息

#### Scenario: 可信目录与专用入口
- **WHEN** 用户选择分析模型，或通过通用任务入口伪造分析 operation/metadata
- **THEN** 首发仅接受服务端可信目录的系统/逻辑视觉文本模型；服务端按实际路由和资源大小验证能力，能力未知、自定义能力声明及通用入口伪造均被拒绝，执行或重路由时不得降级为无图模型

### Requirement: 可见字段白名单与不确定性
系统 SHALL 仅输出角色 appearance、physique、clothing、props 或场景/道具 description、prompt。系统 MUST 在服务端校验结构、类型、长度及白名单；不得生成姓名、性格、关系、声音或虚构置信度，不确定内容留空或待确认。

#### Scenario: 有效但部分不可见
- **WHEN** 角色图片只清晰显示衣着而体型无法判断
- **THEN** 草稿提供可见衣着，体型留空或待确认，不能推测不可见内容

#### Scenario: 模型注入或非法结构
- **WHEN** 模型返回声音设定、资源字段、超长内容、无效 JSON 或嵌入控制指令
- **THEN** 非白名单内容不能成为可采用字段，非法草稿返回安全失败且不执行内容中的指令

#### Scenario: 字段类型与长度边界
- **WHEN** 模型返回草稿字段或超过输出预算
- **THEN** 所有白名单字段只接受 string（包括角色 props），空串表示未知；拒绝数组、对象、null、重复键和多余键，原文最多32 KiB UTF-8，每字段最多2,000 Unicode code points，超限安全失败而非截断

#### Scenario: 原始模型流不可公开
- **WHEN** 用户查看运行中分析、任务详情、事件流或诊断，或模型返回未通过校验的文本
- **THEN** 系统不持久化或广播本分析的原始文本 delta，不通过其他任务出口暴露原文、reasoning 或失败 TextDraft；仅成功提交已校验草稿后允许预览和采用，错误仅返回脱敏原因

### Requirement: 字段审阅与原子采用
系统 SHALL 展示字段当前值、建议值及可选状态，仅按用户明确选中的非空字段提交一次采用。服务端 MUST 从任务的已校验草稿取得值，重新校验目标与基准，原子创建新版本；保留未选字段、参考图、声音和全部既有表现。

#### Scenario: 选择部分字段
- **WHEN** 用户仅选择 clothing 和 props 并确认
- **THEN** 仅这两个字段进入新版本，未选字段和参考图、声音、表现不变，取消审阅不会写入

#### Scenario: 客户端伪造采用内容
- **WHEN** 客户端提交草稿没有的字段或替换字段值、任务 ID、来源或目标资产
- **THEN** 服务端拒绝且不产生新版本

#### Scenario: 历史字段类型与媒体来源保留
- **WHEN** 旧档案 props 是数组或其他 JSON 类型，用户审阅并选择部分字段
- **THEN** 未选字段保持原 JSON 类型和值，选中 props 前明确提示整个字段替换为文本；复制表现保留真实原媒体任务溯源，不将分析任务伪装成媒体生成任务

#### Scenario: 采用收据保留键防注入
- **WHEN** 普通 definition 写入或不可信模型内容试图新增、删除或改写 `_profileAnalysisAdoption`
- **THEN** 系统保护服务端保留键，不允许客户端或模型伪造采用事实；正常新版本可继承收据但不成为新的采用记录，历史版本保留原始采用结果、来源及必要幂等凭据

### Requirement: CAS 与采用幂等
系统 SHALL 要求任务基准版本、请求 expectedVersionId 和当前主版本一致；首次采用后重复相同请求返回同一采用结果而不再次创建版本，同一幂等键的不同请求必须冲突。

#### Scenario: 并发编辑后采用
- **WHEN** 分析后资产已被其他编辑更新
- **THEN** 采用返回机器可读版本冲突，保留草稿供对照，不覆盖最新版本或自动重跑分析

#### Scenario: 响应丢失后的重放
- **WHEN** 同一采用成功但响应丢失，用户重放相同请求
- **THEN** 返回原采用版本与当前资产状态，不重复推进版本或回退 UI

#### Scenario: 陈旧普通素材同步不得回退采用版本
- **WHEN** 采用已把有版本资产推进到新主版本，另一客户端随后通过普通素材同步提交旧主版本或遗漏主版本的快照
- **THEN** 服务端在现有写入事务中拒绝并返回机器可读版本冲突，保留当前主版本、采用字段/收据、表现及关联项目状态；相同当前主版本的元数据编辑和未版本化素材同步继续有效，不静默切换基准后覆盖

### Requirement: 历史基准安全读取
系统 SHALL 在专用分析详情提供经用户、项目、资产和任务授权的baseline，仅包含对应分类允许分析的原始字段，保留JSON类型及missing/null差异。列表和通用任务输出 MUST NOT 包含完整历史definition或收据。

#### Scenario: 编辑后重新打开分析
- **WHEN** 用户重新打开旧基准的分析任务
- **THEN** 显示该任务绑定历史版本的真实baseline、独立更新的当前值及建议值；无法读取基准时明确不可用并禁止首次采用，不以当前值冒充；任务清理后仍返回404且只允许既有采用收据的精确重放

### Requirement: 媒体表现版本身份
系统 SHALL 以版本内角色唯一约束保障表现身份，允许不同版本保留同一原始媒体任务溯源；首次注册与采用重放 MUST 校验目标资产/资源，不将后续复制版本误认为原采用版本。

#### Scenario: 原媒体任务表现跨版本复制
- **WHEN** 用户采用文字档案并保留既有图片表现，随后重放原图片采用
- **THEN** 新版本表现保留原TaskID，版本内无重复角色，重放返回原图片采用版本和当前资产，不误返回复制版本

#### Scenario: 合法历史镜头任务结果登记
- **WHEN** 原媒体任务绑定的镜头版本仍属于该镜头，但当前镜头已更新，随后登记或重放原任务结果
- **THEN** 保留原媒体版本、任务和镜头版本溯源，历史镜头产物以stale且未选中登记，不替换当前选择或修改当前step/instance进度及输出；事务内继续拒绝以ready或selected提升陈旧镜头结果、跨镜头版本、已删镜头及失效工作流，不回退当前状态

### Requirement: 分析来源保护与保守素材删除
系统 SHALL 对所有既有素材删除入口（含清空/强制清除、管理员删除和闲置清理）检查业务引用，覆盖分析任务来源及历史版本；有引用时拒绝并提供来源。只有无引用且完整物理身份/变体及全部生产者结算证据满足现有安全条件时，才允许持久化删除意图并进入不可新增引用的删除中状态。系统 MUST 保留资产、历史及未完成资源记录，直到必要物理对象全部成功后才完成记录清理；证据不足必须拒绝物理清理及最终业务记录清理，不以TTL、业务failed/ready或删除重试次数替代停写证明。本change不承诺所有可能生产者均能完整恢复或所有对象最终可删。

#### Scenario: 失败与部分物理完成
- **WHEN** 删除失败、进程中断或一批对象仅部分物理删除成功
- **THEN** 保留资产、历史、未完成资源记录与持久删除意图，仅在安全条件成立时幂等重试，不恢复为ready、不宣称整批已完成；保留已实现写入状态栅栏，迟到Start/发布/业务写回不能复活已删除或删除中资源，不把业务写回被拒绝当作所有外部写者已停止的证明

#### Scenario: 共享对象与迟到引用
- **WHEN** 多个资源记录共享物理对象，或排队后出现引用/身份变化
- **THEN** 保留被非删除记录使用的物理对象，worker按完整存储身份、必要变体、引用和租约复检；引用写入检查删除状态，不越过保护。仅证据完整的删除组可完成；遇到未知写者或身份/结算证据不足继续保留并明确阻断，不承诺这些组在本change内最终可删

#### Scenario: P1生产者操作结果未知
- **WHEN** 新的物理写入开始，或者业务已失败/成功但潜在物理请求尚无可靠终态
- **THEN** 写前持久化操作及冻结身份，分别记录业务结果与物理结算；删除准入、物理执行前及最终完成检查同物理身份的全部未决操作，后续成功不覆盖旧unknown，不以TTL、业务状态或SDK最后一次响应推定已停写

#### Scenario: P1旧记录缺少结算证据
- **WHEN** 资源或必要变体没有可信操作记录，包括旧ready/failed记录
- **THEN** 不自动回填settled，不物理清理或最终清理业务记录，保留证据不足状态；旧数据维护移至后续change，P1交付只证明其限定安全性质

#### Scenario: P2新协议本地生产者中断
- **WHEN** 遵守新锁协议的本地Go原件生产者中断，授权删除流程尝试恢复
- **THEN** 事务外取得同物理身份OS排他锁，原事务内重新核对完整集合/权限/引用并原子fence、结算和stage；迟到Start和业务写回必须被同事务CAS拒绝，缺少成功证据不能发布ready，失败全部回滚

#### Scenario: 保留未闭合恢复范围的安全阻断
- **WHEN** 旧P1、无记录、playback或远端义务未决，或公告/ReplaceAssets路径无受保护恢复能力
- **THEN** 继续保守拒绝物理清理及最终业务记录清理，不把取得Go进程锁当作子进程或远端停写证明，不隐式维护旧数据；保留已完成P1/P2/P3-B及有限C1成果，本项验收阻断行为，完整恢复能力留给后续change

#### Scenario: 移出完整恢复及维护验收
- **WHEN** 后续需要全部控制者丢失恢复、真实远端所有写入attempt/会话/版本/parts结算，或未知旧缩略图的可信归属及维护
- **THEN** 分别进入[完整生产者恢复](../../changes/add-resource-producer-full-recovery/proposal.md)、[远端物理结算](../../changes/add-remote-storage-physical-settlement/proposal.md)、[旧资源证据维护](../../changes/add-legacy-resource-evidence-maintenance/proposal.md)，各自按具体方案及环境/操作授权验收；不以本change完成代替其通过，不默认启用产品入口或授予业务库、云端、系统权限

### Requirement: 取消恢复与资源生命周期
系统 SHALL 保留可按权限恢复的分析状态和脱敏失败原因，支持取消任务并阻止取消后迟到结果被采用；来源在有效任务、草稿或历史版本引用期间受删除保护，未采用草稿不能造成资产写入。

#### Scenario: 取消与迟到结果
- **WHEN** 用户取消任务后模型仍返回结果，或关闭弹窗后重新打开
- **THEN** 显示真实取消/完成状态，取消任务结果不可采用，关闭弹窗不等于取消或保存

#### Scenario: 失败和资源删除竞争
- **WHEN** 模型失败、响应格式错误，或源资源删除与任务/采用并发
- **THEN** 任务可追踪且错误不含密钥或敏感 URL，已引用资源不被物理删除，失败不改变资产或重复收费调用

#### Scenario: 取消与完成的终态赢家
- **WHEN** 本分析的取消与成功提交并发，或上游已接受运行中请求
- **THEN** 以数据库条件更新成功者决定终态；取消先成功则迟到完成不可采用，完成先成功则取消返回状态冲突并刷新真实结果，重复取消已取消任务幂等；逻辑取消只尽力停止上游，费用沿既有退款/待核对流程处理，不承诺供应商停止或退费
