## 已确认事实与调用链

- 插件目录已有声明式 provider/workflow 注册和生成脚本，宿主自动加载官方插件包。官方 MiniMax 的协议身份、2K 映射和素材约束与 Fisher 不同。
- 画布和创作页主要提交后端生成任务；模型连接测试另走前端 video transport。两条路径均需要 Fisher 适配。
- 渠道设置支持空 Key 保存，但协议选择不会自动填入供应商 Base URL。增加一个现有渠道流程内的 Fisher 预设即可满足后续只填 Key 的需求。
- 任务 metadata/providerOptions 已支持厂商参数和模型默认参数合并，媒体有稳定 ID；不用增加数据库字段。
- 通用能力目前只计总图片/音频，不能表达参考图、关键帧、参考音频和驱动音频的独立额度。参考选择与提示词提及会过滤实际提交素材。
- 后端已有 ProviderRequestID、提交不确定保护及恢复轮询；当前 HTTP 错误、中转和声明式适配未保留 X-Task-Id。API 调用日志已有任务状态同步入口。
- normalizeVideoDuration 只做整数与最小值处理，没有全局 15 秒上限；Fisher 仍须在提交前拒绝非整数输入，不能依赖通用 UI 归一化。

## 确认的技术方案

1. 新增独立 fisher-h3-video 插件，显示 Fisher-H3，模型名 MiniMax-H3，默认地址 https://api.work-fisher.com。复用现有插件生成脚本、Bearer 鉴权、媒体上传和异步轮询。
2. 在现有添加渠道入口提供 Fisher-H3 预设，预填地址、模型和协议，Key 留空。管理员模型设置也能选择同一协议；不修改账号数据库或其他渠道。
3. 在画布和创作页现有参考/参数区域增加 Fisher 专属角色及参数控件：首/尾帧、驱动音频、音频模式、去噪、驱动作为参考、各视频起始偏移。复用实际共享输入组件，不另建生成页。
4. 扩展选项放在 providerOptions["fisher-h3-video"]：驱动音频与视频偏移以稳定媒体 ID 关联；关键帧沿现有选择元数据传递。显式选中的素材加入实际提交集合，引用失效时报错；重试恢复同一组选项。
5. 通用能力只表达总输入容量：最多 11 张图片、4 条音频、3 条视频和 4–60 秒时长范围；Fisher 专属校验严格区分 9 张参考图与各 1 张首尾帧、3 条参考音频与 1 条驱动。普通任务只接受 4–15 秒，有驱动才允许 60 秒；UI 根据实际驱动限制时长。
6. 前端请求映射与后端信任边界分别验证契约；不复用官方 MiniMax 的 slice、2K 替换、强制 adaptive 和 15 秒裁剪。音频默认值以字段是否存在解析，保留 0/false；视频偏移不按数组下标绑定。
7. 保留创建错误的有效 X-Task-Id，经现有任务状态持久化及中转返回继续查询。无有效 ID 的超时、5xx、无效 JSON 不重新 POST；request_id 不能作为 Fisher 任务 ID。认证路径只增加本协议需要的创建及查询权限。
8. 参数说明注明 1080P 原生尺寸对齐（16:9 为 1920×1088）和按请求秒数计价，不在通用尺寸推算中把估算显示成实际输出保证。

## 关键取舍与风险

- 独立插件比直接修改官方 MiniMax 多一个注册项，但协议身份明确，可以分别校验 Fisher 扩展。
- 复用通用容量加 Fisher 角色校验，比扩展所有供应商能力 schema 改动少；两条付费路径必须覆盖角色校验，不能把总容量当作任意角色额度。
- 上游媒体时长未知时使用既有媒体探测/上游校验；已有时长必须验证每条参考视频及偏移剩余均为 2–15 秒，不静默删除素材。
- 不确定提交需要先保存任务 ID 再恢复；日志或状态写入失败不能伪装成安全可重建的任务。
- 没有真实 Key，专项检查可验证请求和状态机，无法证明上游真实生成成功。

## 测试策略

- Bun 最小专项检查：渠道预设空 Key、分辨率/比例、普通与驱动时长、角色独立计数、固定比例/尾帧、显式 0/false、媒体 ID 关联与偏移、实际提交集合和恢复选项。
- Go 最小专项检查：真实声明式插件 payload/响应，后端参数校验，终态处理，X-Task-Id 错误恢复及禁止重复创建，中转鉴权与响应头保留。
- 按改动风险运行相关测试与前端构建；无真实 Key 的付费验收记录在 pending-test，不启动开发服务或发起付费生成。
- 同步模型接入专题、功能及待验收文档。现有模型的行为通过相邻专项检查确认。
