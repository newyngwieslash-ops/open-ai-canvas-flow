# 画布同步一致性修复

## Why

保存或重新打开带本地编辑的画布时，只推进远端基线却保留旧节点列表，会把远端新增节点误判为本地删除。已删除节点的三条残留引用被写入待确认请求，反复返回端点不存在并阻塞助手。

## What Changes

- 保存确认和打开画布都同步处理基线、当前内容与实时编辑器，复用现有三方合并。
- 待确认请求先按原身份重放；明确拒绝的纯悬空连线请求在严格核对快照后恢复。
- 缺少可信旧基线时保留本地内容并报告冲突，不把最新远端状态当作用户编辑前的状态。
- 完整读取、合并与本地持久化成功后才清除 journal。

## Capabilities

无新增能力或规格变更；恢复既有“未确认编辑不被覆盖、删除节点不自动恢复、原请求幂等重放”的合同。

## Impact

修改 user-data-sync.ts、一个同步回归测试文件和两份同步/验收文档；不改公共 API、数据库、依赖或生成任务。已有元数据同值回写提交是前置修复，本变更不重做它。

## 证据与归属

- 前序回归已复现仅改标题却误发 remove_node/remove_connection，以及纯悬空连线 journal 重试失败。
- 用户提供请求为 baseRevision 345，只有三条 create_connection，目标均为已删除节点；无 create_node。
- 本轮补充打开画布场景的失败测试。当前分支工作获用户确认；上述四个文件内本任务修改纳入，其余后端、启动脚本、AGENTS、其他文档和历史 Comet 状态修改原样保留。
