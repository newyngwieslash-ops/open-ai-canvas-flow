# 画布同步一致性修复

## Why

保存或重新打开带本地编辑的画布时，只推进远端基线却保留旧节点列表，会把远端新增节点误判为本地删除。已删除节点的三条残留引用被写入待确认请求，反复返回端点不存在并阻塞助手。

## What Changes

- 保存确认和打开画布都同步处理基线、当前内容与实时编辑器，复用现有三方合并。
- 待确认请求先按原身份重放；明确拒绝的纯悬空连线请求在严格核对快照后恢复。
- 缺少可信旧基线时保留本地内容并报告冲突，不把最新远端状态当作用户编辑前的状态。
- 完整读取、合并与本地持久化成功后才清除 journal。
- 旧缓存完整基线已丢失时，从受归属校验的指定版本回执读取历史文档；ID、revision、内容哈希均一致才合并。

## Capabilities

后续验收发现会话重建后仍可能缺少基线。新增测试复现：加载成功后编辑并重新初始化会话，再收到远端新增节点，Agent 刷新报“缺少画布合并基线”；旧缓存与远端版本及哈希一致时，Agent 刷新也没有复用安全恢复路径。另查明助手审批等待所有画布，其他画布同步失败会阻塞当前画布。持久化修复只能防止后续丢失，不能还原旧客户端未保存的基线。用户已明确选择“沿用当前修复流程完成”，同意继续 hotfix 增加历史版本只读接口，复用现有完整操作回执恢复旧基线。

增加 `GET /canvas-projects/:id/revisions/:revision`，恢复既有“未确认编辑不被覆盖、删除节点不自动恢复、原请求幂等重放”的合同；不增加历史恢复写操作。

## Impact

修改同步服务、助手现有保存调用、历史版本读取的 repository/domain/service/handler 路径及对应测试、OpenAPI 和同步文档；不改数据库结构、依赖或生成任务。已有元数据同值回写提交是前置修复，本变更不重做它。

## 证据与归属

- 前序回归已复现仅改标题却误发 remove_node/remove_connection，以及纯悬空连线 journal 重试失败。
- 用户提供请求为 baseRevision 345，只有三条 create_connection，目标均为已删除节点；无 create_node。
- 本轮补充打开画布及旧缓存历史恢复的失败测试。当前分支工作获用户确认；仅纳入本任务文件，后端 Agent/尺寸、启动脚本、AGENTS、其他文档和历史 Comet 状态修改原样保留。
