# Proposal

## Why

项目目前只在部分前端字标上把“影策”映射为“源铭振跃”，后端默认身份、注册协议、邮件、Agent、插件元数据及大量文档仍使用旧品牌，直接切换配置或导入插件会再次暴露旧名。用户明确要求项目中的所有旧品牌元素统一替换，因此本次从局部 UI 显示扩展为完整产品品牌一致性变更。

## What Changes

- 前后端默认品牌、SEO/分享元数据、版权展示、管理端恢复默认提示、注册协议默认标题与邮件身份统一为“源铭振跃”；检查当前存量外观、画布 Agent、邮件与注册设置中的旧默认值。
- 保留已有自定义配置的非品牌字段及创作数据；从现有配置读取/规范化入口解决旧品牌残留，避免只在组件里遮盖旧名。
- 更新所有产品自有的助手提示词、预演工作台、技能库、插件作者显示名、导出与诊断展示文本、说明文档及源代码注释；中文品牌技能目录改名时同步引用和嵌入路径。
- 检查产品使用的图片、SVG、截图、视频和压缩包。对含旧品牌像素的实际界面重新截图；对插件源码、内嵌文档及实际可分发包同时更新并核对内容一致性。
- 对可见的 YINGCE / Yingce 品牌副标采用“源铭振跃”或中性功能说明；不虚构英文商标或擅自修改技术 slug。
- 增加品牌残留审计及关键行为回归，交付逐项残留说明，区分实际品牌残留与必要的旧数据识别字符串。
- 本次作为一个变更执行：目标是同一品牌身份在不同载体上的一致性，不引入独立新功能，拆分交付会留下新旧品牌混用。

## Capabilities

### New Capabilities

- `product-brand-identity`：统一默认产品身份、存量设置的品牌解析、产品自有内容与分发素材的品牌一致性，以及可审计的残留边界。

### Modified Capabilities

无。现有主规格集中在视频提供商、资源绑定和用户同步，没有产品品牌身份规格。

## Impact

- 代码：`web/src` 的外观、认证、Agent、插件及编辑器；`backend/internal/app`、`auth`、`skills`、`prompts`、OpenAPI；内置技能与插件源包；产品相关脚本及文档。
- 素材：`assets/`、`web/public/`、`docs/public/` 中实际使用的产品品牌图文；`plugin-packages/*.yingce-plugin` 内的清单和文档。
- 基线扫描发现 377 个含中文旧品牌的文本文件（592 行）以及 105 个插件包中的 94 个包内命中；这不是未经分类的批量替换清单，详见 `brand-inventory.md`。
- 没有数据库表结构、新公共 API 或新依赖。API 路径、Go module/import、环境变量、Cookie、持久缓存键、插件 schema/ID/扩展名、部署服务与镜像地址属于兼容标识，保持可读可运行。
- 不改用户项目/聊天/素材内容，不删除上传资源，不覆盖其他自定义品牌；保留实际第三方作者、上游许可和真实外部链接，不重写 Git 历史，不发布/推送/部署。
- 既有未提交欢迎页改动是本轮已完成的视觉输入，原样保留；`.taste-skill/` 和用户参考图是独立工作区输入，不作产品品牌资产覆盖。
- 关键待核实项：已运行实例的具体品牌设置、图片/视频中的像素残留、插件实际打包入口及校验信息。实施阶段先只读核实，再选择最小更新路径。
