# Proposal

## Why

项目目前只在部分前端字标上把“影策”映射为“源铭振跃”，后端默认身份、注册协议、邮件、Agent、插件元数据及大量文档仍使用旧品牌，直接切换配置或导入插件会再次暴露旧名。用户明确要求项目中的所有旧品牌元素统一替换，因此本次从局部 UI 显示扩展为完整产品品牌一致性变更。

## What Changes

- 前后端默认品牌、SEO/分享元数据、版权展示、管理端恢复默认提示、注册协议默认标题与邮件身份统一为“源铭振跃”；检查当前存量外观、画布 Agent、邮件与注册设置中的旧默认值。
- 保留已有自定义配置的非品牌字段及创作数据；从现有配置读取/规范化入口解决旧品牌残留，避免只在组件里遮盖旧名。
- 更新所有产品自有的助手提示词、预演工作台、技能库、插件作者显示名、导出与诊断展示文本、说明文档及源代码注释；中文品牌技能目录改名时同步引用和嵌入路径。
- 检查产品使用的图片、SVG、截图、视频和压缩包。对含旧品牌像素的实际界面重新截图；对插件源码、内嵌文档及实际可分发包同时更新并核对内容一致性。
- 对可见的 YINGCE / Yingce 品牌副标采用“源铭振跃”或中性功能说明；不虚构英文商标或擅自修改技术 slug。
- 增加品牌残留审计及关键行为回归，交付逐项残留说明，区分实际品牌残留与必要的旧数据识别字符串。
- 本次作为一个变更执行：目标是同一品牌身份在不同载体上的一致性，不引入独立新功能，拆分交付会留下新旧品牌混用。

## Capabilities

### New Capabilities

- `product-brand-identity`：统一默认产品身份、存量设置的品牌解析、产品自有内容与分发素材的品牌一致性，以及可审计的残留边界。

### Modified Capabilities

无。现有主规格集中在视频提供商、资源绑定和用户同步，没有产品品牌身份规格。

## Impact

- 代码：`web/src` 的外观、认证、Agent、插件及编辑器；`backend/internal/app`、`auth`、`skills`、`prompts`、OpenAPI；内置技能与插件源包；产品相关脚本及文档。
- 素材：`assets/`、`web/public/`、`docs/public/` 中实际使用的产品品牌图文；`plugin-packages/*.yingce-plugin` 内的清单和文档。
- 基线扫描发现 377 个含中文旧品牌的文本文件（592 行）以及 105 个插件包中的 94 个包内命中；这不是未经分类的批量替换清单，详见 `brand-inventory.md`。
- 没有数据库表结构、新公共 API 或新依赖。API 路径、Go module/import、环境变量、Cookie、持久缓存键、插件 schema/ID/扩展名、部署服务与镜像地址属于兼容标识，保持可读可运行。

# Design

## Context

动机和范围见 proposal.md；验收合同见 specs/product-brand-identity/spec.md。

当前前端 displayBrandName/displayBrandTitle 只在展示层映射，后端外观、认证域和画布 Agent 各有旧默认值。readAppearance 会用已保存 JSON 覆盖新默认值，随后邮件发件人和默认协议又继承这个身份。因此仅改默认常量或 UI 文本都会遗漏存量实例。

实际插件包包含清单与内嵌契约文档；源码搜索不覆盖归档条目。图片中的旧名也不属于字符串检索范围。现有欢迎页与相关测试改动属于已获授权的前序工作，须保留。

## Goals / Non-Goals

**Goals:** 在已有品牌配置链路、内置内容更新和分发链路上完成一致改名；把存量设置与非文本内容作为验收路径；保留一份可核验的残留清单。

**Non-Goals:** 不建立新的主题/品牌框架，不更换中性图形或增加依赖，不重命名机器协议和数据定位键，不调整既有欢迎页设计；不以恢复默认、清库、清缓存或重装插件完成改名。

## Decisions

### 1. 从真实品牌入口统一，不继续增加显示补丁

同步后端、认证域与前端降级默认值，沿已有 appearance 解析与消费链路更新品牌。前端已有展示映射在实施时消除重复真相，所有调用仍保留自定义外观和 Logo 回退合同。

替代方案：只扩大字符串显示映射。放弃原因：邮件、协议、配置 API、插件元数据与导出仍会得到旧身份，无法满足全项目目标。

### 2. 存量更新限定明确的全局品牌字段

先只读检查运行实例和字段归属；在既有读取/规范化/受保护保存路径处理旧默认品牌及其明确派生文案，保持管理读取与公开读取一致。邮件旧默认名的“继承站点名”语义需保留，Agent 自定义名称与其他品牌不覆盖。修改后的默认或保存值在重启后仍一致，不引入数据库 schema。

保存设置时必须保留完整原对象和所有无关字段；若实施需要持久写入，先保存受权限保护的原值快照，再通过现有合法更新路径进行。仅为识别旧默认值所需的旧字面量集中标记为迁移例外，不散落到产品输出。

替代方案：重置 appearance 或全库 replace。放弃原因：会删除媒体/主题等配置或改写用户创作内容。

### 3. 共享元数据及实际包内内容同步

优先在元数据的真实源头更新作者、技能名称和说明，保留稳定 ID。检查内置内容种子和已安装官方条目的更新机制，确保源码更新能反映到现有实例，保留管理员自定义编辑。中文目录改名须同步全部引用及嵌入规则。

按现有打包入口重新生成实际分发包，核验清单、内嵌文档、内容摘要及宿主导入。不能以文件名不含中文、压缩包二进制搜索无命中替代解包检查。

### 4. 视觉资产与文档逐项核验

按实际引用检查截图、SVG、内嵌页面与品牌视频；产品截图以干净会话中的真实页面重截。更新本项目品牌说明、当前维护文档、脚本显示与 OpenAPI 标题，保留实际第三方 Logo/作者、许可证和外部仓库地址。未引用的旧品牌资产也须记录，决定重截、替换或仅作为明确的历史参考保留。

### 5. 残留按语义分类

维护一个聚焦的可运行品牌扫描检查，覆盖文本、文件名、归档条目及受影响素材清单；例外必须精确到文件和用途，不以宽泛目录白名单隐藏产品文案。Git 历史、用户参考文件、必要迁移/回归输入和稳定机器标识不能被误报为当前品牌展示。用户内容中的品牌提及也不批量变更。

## Risks / Trade-offs

- [旧配置覆盖新默认值] → 回归覆盖空配置、旧默认配置、其他自定义品牌、完整配置保存与重启读取。
- [已安装技能/插件仍展示旧元数据] → 校准更新链路并验证现有安装，不只验证新包文件。
- [元数据改名意外触发协议或存储变更] → 技术 ID/键与生成参数保持不变，执行导入和旧数据读取检查。
- [图片或视频无法完成运行检查] → 明确记为未完成，不能宣称“全部已替换”；优先使用当前运行环境和真实路由。
- [旧研究方案仅授权 UI 显示，与本次范围冲突] → 本次用户明确要求优先，旧方案作为参考证据，不作为继续保留旧产品身份的依据。
- [工作区混有先前改动] → 只叠加本次品牌相关修改，不重置、覆盖或擅自提交独立的参考图/工具产物。

## Migration Plan

先保存扫描基线与必要设置备份，再更新真实默认和规范化入口，随后更新内容源、视觉资产及分发包。运行专项测试、构建和真实路由验收后记录残留及未覆盖路径。本次不自动部署或推送。

回滚只回退本次独立品牌补丁与由本次写入的设置快照；不删除用户项目、上传文件、数据库或前序欢迎页改动。

## Open Questions

运行实例有哪些全局字段仍保存旧名、归档包由哪个现有脚本生成、视频是否含品牌像素，均可通过只读检查确定；不改变上述目标和验收边界。对不可访问的设置或素材需如实记录，不以默认推断代替检查。

# 产品品牌身份

## Purpose

确保“源铭振跃”作为同一产品身份贯穿界面、后台默认值、系统通信、内置创作能力、文档与分发素材。覆盖新安装和存量配置，防止界面展示已改名而邮件、插件、图片或管理操作仍暴露旧品牌，同时保留实际业务数据及机器可读合同。

## ADDED Requirements

### Requirement: 默认产品品牌一致
系统 SHALL 在产品自有的可见文字、默认设置、页面和分享元数据、无障碍标签、助手自述、导出展示、邮件身份和默认协议标题中使用“源铭振跃”，不得向用户展示旧默认品牌或其英文品牌副标。

#### Scenario: 新安装与前端失败降级
- **WHEN** 新安装没有保存外观设置，或前端获取公开外观失败而使用内置默认
- **THEN** 登录、创作、欢迎页、后台、预演、画布助手与元数据均使用新品牌，刷新和导航不闪回旧名

#### Scenario: 系统通信与管理操作
- **WHEN** 读取默认注册协议、通过隔离邮件发送器生成邮件、查看内置作者或恢复默认操作的提示
- **THEN** 用户看到的新默认身份均为“源铭振跃”，测试不发送真实邮件且不执行破坏性的恢复默认操作

### Requirement: 存量设置更新不得覆盖其他配置
系统 MUST 处理仍保存旧品牌的产品全局身份文案及内置内容元数据，使其与新品牌一致；只更新明确品牌字段，不以重置整个配置的方式改名。其他自定义品牌、Logo、媒体、主题、备案、额度、密钥及用户创作内容 MUST 保持原值。

#### Scenario: 旧外观和默认发件人
- **WHEN** 既有实例的品牌、SEO、Agent、默认协议或继承式邮件发件人仍使用旧默认身份
- **THEN** 公开读取、管理读取和通信采用新身份，其他字段无丢失，保存与重启后不重新显示旧品牌

#### Scenario: 自定义配置保护
- **WHEN** 实例采用其他自定义品牌和 Agent，或用户项目、提示词正文、聊天和素材中提及旧名
- **THEN** 这些用户内容及其他品牌保持不变，品牌替换不清库、不清缓存、不改资源归属

#### Scenario: 已安装内置内容
- **WHEN** 现有实例已经安装含旧品牌的官方技能或插件元数据
- **THEN** 官方品牌展示随更新变为新名称，稳定内容 ID 与用户自定义编辑保持可识别且不产生重复安装

### Requirement: 产品自有内容和分发包一致
系统 SHALL 将当前维护的产品说明、内置技能名称、插件作者展示、嵌入文档及分发包内的品牌同步更新。目录或文档改名 MUST 同步真实引用；不能只改包外文件而保留包内旧文案。

#### Scenario: 插件解包与读取
- **WHEN** 检查更新后的插件源码与实际可分发包，或在宿主中读取其作者和说明
- **THEN** 两者均采用新品牌，包的协议、供应商参数、资源路径和导入行为保持有效

#### Scenario: 技能目录和文档
- **WHEN** 读取、嵌入或加载更名后的产品自有短剧技能与文档
- **THEN** 展示名称和说明使用新品牌，引用无断链且稳定技能 ID 不改变

### Requirement: 非文本素材不得遗留旧品牌展示
产品实际引用的图片、截图、SVG、视频及内嵌页面 SHALL 一并检查品牌文字与标识。含旧品牌的产品截图 MUST 从改名后的真实应用重截；第三方 Logo、作者头像、上游许可和真实出处 MUST 不被冒充或抹去。

#### Scenario: 图片与视频中的旧名
