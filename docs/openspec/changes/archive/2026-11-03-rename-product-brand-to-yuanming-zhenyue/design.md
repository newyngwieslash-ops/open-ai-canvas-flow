# Design

## Context

动机和范围见 proposal.md；验收合同见 specs/product-brand-identity/spec.md。

当前前端 displayBrandName/displayBrandTitle 只在展示层映射，后端外观、认证域和画布 Agent 各有旧默认值。readAppearance 会用已保存 JSON 覆盖新默认值，随后邮件发件人和默认协议又继承这个身份。因此仅改默认常量或 UI 文本都会遗漏存量实例。

实际插件包包含清单与内嵌契约文档；源码搜索不覆盖归档条目。图片中的旧名也不属于字符串检索范围。现有欢迎页与相关测试改动属于已获授权的前序工作，须保留。

## Goals / Non-Goals

**Goals:** 在已有品牌配置链路、内置内容更新和分发链路上完成一致改名；把存量设置与非文本内容作为验收路径；保留一份可核验的残留清单。

**Non-Goals:** 不建立新的主题/品牌框架，不更换中性图形或增加依赖，不重命名机器协议和数据定位键，不调整既有欢迎页设计；不以恢复默认、清库、清缓存或重装插件完成改名。

## Decisions

### 1. 从真实品牌入口统一，不继续增加显示补丁

同步后端、认证域与前端降级默认值，沿已有 appearance 解析与消费链路更新品牌。前端已有展示映射在实施时消除重复真相，所有调用仍保留自定义外观和 Logo 回退合同。

替代方案：只扩大字符串显示映射。放弃原因：邮件、协议、配置 API、插件元数据与导出仍会得到旧身份，无法满足全项目目标。

### 2. 存量更新限定明确的全局品牌字段

先只读检查运行实例和字段归属；在既有读取/规范化/受保护保存路径处理旧默认品牌及其明确派生文案，保持管理读取与公开读取一致。邮件旧默认名的“继承站点名”语义需保留，Agent 自定义名称与其他品牌不覆盖。修改后的默认或保存值在重启后仍一致，不引入数据库 schema。

保存设置时必须保留完整原对象和所有无关字段；若实施需要持久写入，先保存受权限保护的原值快照，再通过现有合法更新路径进行。仅为识别旧默认值所需的旧字面量集中标记为迁移例外，不散落到产品输出。

替代方案：重置 appearance 或全库 replace。放弃原因：会删除媒体/主题等配置或改写用户创作内容。

### 3. 共享元数据及实际包内内容同步

优先在元数据的真实源头更新作者、技能名称和说明，保留稳定 ID。检查内置内容种子和已安装官方条目的更新机制，确保源码更新能反映到现有实例，保留管理员自定义编辑。中文目录改名须同步全部引用及嵌入规则。

按现有打包入口重新生成实际分发包，核验清单、内嵌文档、内容摘要及宿主导入。不能以文件名不含中文、压缩包二进制搜索无命中替代解包检查。

### 4. 视觉资产与文档逐项核验

按实际引用检查截图、SVG、内嵌页面与品牌视频；产品截图以干净会话中的真实页面重截。更新本项目品牌说明、当前维护文档、脚本显示与 OpenAPI 标题，保留实际第三方 Logo/作者、许可证和外部仓库地址。未引用的旧品牌资产也须记录，决定重截、替换或仅作为明确的历史参考保留。

### 5. 残留按语义分类

维护一个聚焦的可运行品牌扫描检查，覆盖文本、文件名、归档条目及受影响素材清单；例外必须精确到文件和用途，不以宽泛目录白名单隐藏产品文案。Git 历史、用户参考文件、必要迁移/回归输入和稳定机器标识不能被误报为当前品牌展示。用户内容中的品牌提及也不批量变更。

## Risks / Trade-offs

- [旧配置覆盖新默认值] → 回归覆盖空配置、旧默认配置、其他自定义品牌、完整配置保存与重启读取。
- [已安装技能/插件仍展示旧元数据] → 校准更新链路并验证现有安装，不只验证新包文件。
- [元数据改名意外触发协议或存储变更] → 技术 ID/键与生成参数保持不变，执行导入和旧数据读取检查。
- [图片或视频无法完成运行检查] → 明确记为未完成，不能宣称“全部已替换”；优先使用当前运行环境和真实路由。
- [旧研究方案仅授权 UI 显示，与本次范围冲突] → 本次用户明确要求优先，旧方案作为参考证据，不作为继续保留旧产品身份的依据。
- [工作区混有先前改动] → 只叠加本次品牌相关修改，不重置、覆盖或擅自提交独立的参考图/工具产物。

## Migration Plan

先保存扫描基线与必要设置备份，再更新真实默认和规范化入口，随后更新内容源、视觉资产及分发包。运行专项测试、构建和真实路由验收后记录残留及未覆盖路径。本次不自动部署或推送。

回滚只回退本次独立品牌补丁与由本次写入的设置快照；不删除用户项目、上传文件、数据库或前序欢迎页改动。

## Open Questions

运行实例有哪些全局字段仍保存旧名、归档包由哪个现有脚本生成、视频是否含品牌像素，均可通过只读检查确定；不改变上述目标和验收边界。对不可访问的设置或素材需如实记录，不以默认推断代替检查。
