# 最小修复方案

复用 mergeAgentCanvasEditor，以旧基线、本地最新内容、远端完整快照执行三方合并。发布前校验账号和编辑快照未变化；基线与本地投影一起推进，避免后续差异生成误删新节点。

打开画布时有 journal，保留原基线和本地编辑，等待原请求重放，不从新远端快照重新生成操作。没有 journal 时只用已验证基线、哈希匹配的完整旧缓存或匹配旧远端哈希的当前远端快照；缺失证据则拒绝猜测并保留编辑。

保存先重放原 mutationId。仅 HTTP 400、整批纯新增连线、同一缺失端点在所有相关快照均不存在、远端连线不存在且版本未倒退时允许清理。合并冲突或读取失败仍保留 journal；后续编辑用新 mutationId 保存。

自动化覆盖保存期间编辑、打开脏画布、真实删除、同字段冲突、未知旧基线、journal 刷新恢复及不允许清理的边界。使用真实同步服务和内存传输替身；最终运行专项测试及前端构建，不提交付费生成任务。

验收修复：使用已有账号隔离 localforage 保存已确认完整快照及旧投影对应基线。轮换前落盘旧投影，避免连续 SSE 覆盖尚未落盘文档的恢复基线。共用基线查找核对 ID、revision、哈希；恢复失败保留编辑并标明画布。全量恢复也用原基线生成操作，不能把最新云端快照当旧基线。助手调用按 canvasId 保存，并行批次结束后补做当前范围保存。

缓存仅保留两份快照，不假装能还原旧客户端未记录的历史。原 Edge 登录会话尚不可访问；自动化通过不能替代当前用户画布的恢复验收。

## 旧缓存恢复

用户刷新后仍收到当前画布缺少确认基线的错误，证明仅防止未来丢失不足以修复已有缓存。只读核查发现问题画布当前为 revision 354、76 个节点，操作回执保留 revision 229–354 的完整 document；常规历史快照仅到 revision 227，不能用常规历史代替最近版本。

复用操作回执补充按版本读取能力：服务端先校验当前用户对现存画布的归属，再按用户、画布和版本读取完整回执文档；不写画布、不重放操作、不恢复已删除画布。浏览器仅在现有恢复来源均不可用时请求本地记录的旧版本，仍须同时通过 ID、revision、内容哈希核对才能作为合并基线。版本缺失、哈希不一致或同字段冲突保留本地编辑。无需数据库迁移和新依赖。

用户已明确选择“沿用当前修复流程完成”，因此继续 hotfix。已实现受归属校验的指定版本 GET，浏览器仅在旧基线核对通过后合并；覆盖权限隔离、缺失版本、损坏回执、哈希不匹配及旧缓存恢复，部署本地后再验证用户画布。
