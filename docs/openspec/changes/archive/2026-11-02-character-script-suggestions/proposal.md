# Proposal

## Why

项目资产页新建角色卡只能手工填写，已有章节资产提取面向单章、批量候选，不能在当前表单中按姓名汇总跨章节信息并逐字段核对依据。新增可审核的剧本建议入口，减少重复整理，同时避免把模型猜测当作角色事实。

## What Changes

- 角色编辑弹窗增加姓名驱动的「从剧本提取」入口，默认选中当前项目全部已保存的剧情章节，展示范围、模型及分析状态。
- 读取真实章节正文，生成指定角色的字段建议；事实附章节与原文，推断、制作建议、未明确和冲突分别展示。
- 无歧义事实可填入未编辑的空字段；其他建议和覆盖操作由用户选择。只有点击原有创建/保存按钮才写入角色。
- 同名人物先选择身份；与项目已有角色姓名或别名匹配时提示查看或补充已有角色。查重覆盖全部分页和文件夹。
- 默认尝试全项目分析；首版超出所选模型预算时明确拒绝提交，允许用户主动缩小章节范围或更换模型，不静默截断，不声称局部结果覆盖全剧本。
- 复用现有后端文本任务、项目读取、角色创建/更新及同步链路，不新增依赖、数据库表、业务接口或自主 Agent 系统。

## Capabilities

### New Capabilities

- `project-character-script-suggestions`：项目剧本驱动的角色设定建议、来源核验、人工采纳及既有角色匹配。

### Modified Capabilities

无。保留既有章节批量提取、资产候选确认、图片绑定和云同步合同。

## Impact

- 前端：`web/src/pages/projects/detail/assets.tsx`；新增页面私有建议模块、纯校验模块与专项测试；按需要为现有项目 GET 方法补可选 AbortSignal。
- 复用：`services/api/generation-task.ts`、`services/api/task-center.ts`、`services/api/projects.ts`、现有模型选择器和 `AppModal`。
- 文档：实施完成后更新功能说明及待测试清单；本次仅产出计划，不将计划写成已实现。
- 非目标：自动创建、自动合并角色、后台批量建卡、自动分块长篇检索、刷新后恢复未保存表单、证据持久化、新图片或声音生成。
- 已知限制：引用校验只能证明原文存在，语义准确性仍须人工审核；模型预算是估算；前端查重不提供跨会话并发唯一性保证。
- 待执行前确定：实现 Agent 的工作区/分支与执行配置。技术路线及验收草稿见 design、spec 和 implementation-plan；不阻碍本次计划交付。

本次作为一个 change：提取、依据展示、审核填充和保存边界共同构成一次角色卡操作，不能独立交付其中一段来满足本需求。用户将计划交给另一 Agent 实施，再由原规划 Agent 最终审核。
