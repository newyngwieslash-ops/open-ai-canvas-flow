# Spec Delta

## Purpose

为项目角色卡提供依据已保存剧本整理的字段建议，使用户能够检查姓名匹配、来源原文、跨章节差异及未明确的信息，在审核和编辑后通过原有角色保存流程形成设定，减少重复整理并避免把模型推断误当作剧本事实。

## ADDED Requirements

### Requirement: 显式选择剧本分析范围

系统 SHALL 在角色卡表单提供「从剧本提取」，默认选择当前项目全部已保存剧情章节，展示所选章节及实际读取结果；系统 MUST 读取正文，不得用列表摘要或未保存草稿冒充正文。

#### Scenario: 正常全项目提取
- **WHEN** 用户输入非空姓名并选择可用文本模型开始提取
- **THEN** 系统读取已选章节正文，显示分析章节数，向模型提交该范围的完整可分析文本

#### Scenario: 无正文或读取失败
- **WHEN** 所选章节全部为空，或任一所选章节读取失败
- **THEN** 系统不发起模型任务并说明原因，保留已有表单；空章明确列出为未分析而非虚报覆盖

#### Scenario: 超出模型输入预算
- **WHEN** 完整输入超出所选模型预算
- **THEN** 系统不截断正文、不提交任务，提示更换模型或由用户选择较小范围；缩小后明确标为局部分析

### Requirement: 可核对的字段建议

系统 SHALL 区分剧本事实、推断、制作建议与正文未明确，并展示来源章节和原文。系统 MUST 校验引用属于本次输入且原文存在；存在引用不等于已证实语义。

#### Scenario: 明确事实
- **WHEN** 模型返回有有效原文引用的外貌或人物关系建议
- **THEN** 用户能展开查看章节与原文，并编辑建议值

#### Scenario: 未明确及推断
- **WHEN** 剧本未描述身高或音色，或模型推断性格、提出三视图建议
- **THEN** 未描述的字段标记「正文未明确」且不编造值，推断和制作建议保留独立标签并由用户主动采纳

#### Scenario: 伪造引用与非法结果
- **WHEN** 响应包含不存在的章节、原文不匹配、无引用事实、未知字段或损坏结构
- **THEN** 系统拒绝本次结果，不部分填充表单，提示重新提取或手工填写

### Requirement: 人物歧义和设定冲突需人工选择

系统 MUST 将多个同名人物和字段冲突呈现给用户，不得自动合并身份、自动挑选冲突值或把阶段服装变化写成永久稳定特征。

#### Scenario: 同名人物
- **WHEN** 返回两个不同身份的同名人物
- **THEN** 系统先展示身份描述和依据，用户选定其中一个后才允许应用其字段

#### Scenario: 跨章节差异
- **WHEN** 同一字段存在多个不兼容描述或明显阶段差异
- **THEN** 系统保留带章节依据的多个选项，不自动覆盖该字段，由用户选择、编辑或明确保留空白

#### Scenario: 未找到人物
- **WHEN** 本次范围中没有可识别的目标人物
- **THEN** 系统显示未找到，不清空表单、不生成虚构角色、不调用角色写接口

### Requirement: 建议不得越过用户编辑和保存边界

系统 SHALL 仅将无歧义事实自动填入用户未编辑的空字段。任何已有值、用户改动、推断、制作建议及冲突值 MUST 经用户操作才可替换或采用。角色写入 MUST 由原有创建或保存操作触发。

#### Scenario: 用户先填了内容
- **WHEN** 提取开始前或执行中用户编辑了某字段，包括主动清空字段
- **THEN** 结果不覆盖该字段，建议留在旁边供用户选择

#### Scenario: 关闭或切换后旧请求返回
- **WHEN** 提取期间关闭弹窗、切换项目/账号/角色、修改目标姓名或开始新一轮提取
- **THEN** 旧结果不得修改当前表单，旧错误不得误报为当前轮错误

#### Scenario: 未确认保存
- **WHEN** 结果已展示但用户尚未点击创建或保存
- **THEN** 不创建角色、不更新角色版本、不写资产候选；模型任务记录仍按现有任务生命周期保存

#### Scenario: 保存失败
- **WHEN** 角色保存接口失败
- **THEN** 系统保留表单和可用建议并显示错误，不显示服务端保存成功

### Requirement: 已有角色的姓名和别名匹配

系统 SHALL 在当前项目全部角色中检查规范化姓名和别名，不得受列表分页、搜索或文件夹过滤影响。命中 MUST 提示查看或补充已有角色，禁止自动归并；确实不同身份时允许用户明确选择另建。

#### Scenario: 别名位于另一页或文件夹
- **WHEN** 输入名称命中另一页角色的别名
- **THEN** 系统提示该角色，可打开其设定；不会静默创建重复卡

#### Scenario: 用户选择补充已有角色
- **WHEN** 用户选中一个匹配角色进行补充
- **THEN** 系统加载其当前版本并保留已有值，建议按审核规则应用，最终通过原有更新角色流程保存

### Requirement: 可停止且可理解的提取状态

系统 SHALL 展示读取、提取、审核、失败状态及可操作的停止入口，正确区分停止页面监听、后端取消请求和已确认取消；关闭弹窗不得宣称任务一定停止或费用退回。

#### Scenario: 停止提取
- **WHEN** 用户停止提取且后端任务已经创建
- **THEN** 系统阻止结果应用，发送现有任务取消请求，并按实际响应显示取消状态或取消失败

#### Scenario: 可访问性
- **WHEN** 用户通过键盘、窄屏或深浅主题操作建议表单
- **THEN** 来源、选项、停止与保存入口有可读标签和焦点，状态不只依赖颜色，表单及底部操作可滚动到达
