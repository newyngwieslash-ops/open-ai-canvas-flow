# P3/P4/P5 隔离能力验证

本轮用户明确批准的隔离能力验证及独立审查已完成。实验结果可交付，关键真实性发现已关闭；P3/P4/P5产品能力仍缺证据，不是产品集成验收通过。任务5.2保持未完成，Classic Build 12/13、verify pending、archived=false。

## 授权和证据分层

- P3：实际测试进程/ffmpeg与OS控制能力；候选启动/停止账本单独使用临时SQLite和自产PG，fake-kill不作真实停写证明。
- P4：具名供应商官方合同、实际SDK/产品可隔离调用路径和本地受控协议反例分别记录；本地模拟不作供应商终态保证。
- P5：合成旧对象与可信/缺失身份、归属、未决writer证据；无业务库inventory、回填、实际旧对象接管或删除。
- 无业务库操作、真实云对象写删、凭据读取、付费调用、既有服务重启、特权环境配置或push。原有产品及并发修改保持。

## 已观察结果与独立核证

审查者独立重跑Windows进程探针exit0，核对12个自产PID均退出；P4 storage 1.817s、P5 app 3.770s、修订账本SQLite 1.681s通过。PG依据冻结源码/hash及日志核证；Linux依据源码和运行日志核证，审查者未重复执行。原账本仅排队请求不足以证明实际锁等待的发现E1，已补B真实UPDATE产生ErrBusy/55P03后才放行A，再重试fenced，唯一复核关闭。

P3Linux父死反例证明进程仍活且父锁可取得，不单独断言父死后文件继续增长；Windows迟到writer则有事件屏障后的实际写文件断言。两者不混写。主会话复核本轮backend源码基线2298文件无变化；未为纯实验重跑完整产品构建，也未把P2历史build当P3产品证据。

Windows真实Job：创建时关联及后代继承成立；同一可信句柄可观察全体退出，但TerminateJobObject后active=0仍能接收迟到进程。监督器崩溃可终止测试写者，却不能在所有控制句柄丢失后仅凭同名新Job证明旧代际终态。Windows现有ffmpeg缺libx264，mpeg4只用于实际写者控制，不计作产品转码格式通过。

Linux现有非特权容器为UID1000、cgroup v2只读，没有委派，主候选未验收。实际ffmpeg探针复现父锁释放而子仍活；该构建保留继承flock FD，直到写者退出才可重取，但这只证明该构建/路径，不能泛化未来版本或全部后代。ffmpeg 5.1.6完成H.265/MPEG4各含音频/无音频四场景普通H.264/AAC MP4、faststart、解码与本地字节范围重组；fd协议不存在，不能采用该输出候选。没有以此替代真实产品HTTP Range验收。

P4实际上传helper接loopback的响应丢失/重试反例，与multipart纯HTTP状态机分开记账；四家真实服务恢复终态仍未运行，无provider限制变更。P5真实worker未知thumbnail及跨用户alias保护通过；没有真实可信manifest与维护器，不能称已完成旧数据接管。

## 完成门槛

三个工作包在已授权安全范围内完成最小充分实验并由独立审查核证；关键问题修复后最多一次定向复核，P1/P2及P3设计审查历史不重置。只证明实验覆盖范围，不因本轮完成便勾5.2。若产品实施仍需新增持久字段、部署能力、供应商限制或维护数据，应基于结果提供具体方案与边界，不从实验授权推定执行。
