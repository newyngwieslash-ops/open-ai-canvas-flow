# Fisher-H3 视频生成

在设置的渠道页面添加 Fisher-H3 预设，默认地址为 `https://api.work-fisher.com`，模型名称为 `MiniMax-H3`，请求协议为 `fisher-h3-video`。API Key 留空，可先保存，使用前再填写 Fisher 站点的 Key。管理员也可在系统渠道模型设置中选择 Fisher-H3 协议。协议由明确配置决定，不根据域名或模型名猜测。

该渠道使用本站 Fisher 的 MiniMax V2 格式，与官方 MiniMax 渠道分别配置。插件在现有目录中加载；画布、创作页和模型连接测试使用同一参数合同。生成与媒体保存复用现有任务和资源链路。

## 画面与时长

| 参数 | 支持范围 |
| --- | --- |
| 模型 | 精确名称 `MiniMax-H3` |
| 提示词 | 必须包含非空文本，最多 10000 字符 |
| 分辨率 | 480P、768P、1080P |
| 普通时长 | 整数 4–15 秒 |
| 有独立驱动音频 | 整数 4–60 秒 |
| 固定比例 | 1:1、2:3、3:2、3:4、4:3、9:16、16:9、21:9 |
| adaptive / auto | 仅首帧、尾帧或首尾帧模式，按首帧（只有尾帧时按尾帧）选择最接近的固定比例 |

纯文本必须指定比例；带参考素材省略时为 16:9。明确选择的固定比例不会被关键帧覆盖。1080P 保留原生对齐尺寸，16:9 为 **1920×1088**；输出按 17n+5 帧对齐可能略长，按请求秒数计价。界面的尺寸估算不是上游任意尺寸输出承诺。

## 参考素材与驱动音频

在现有参考/参数区域选择首帧、尾帧、驱动音频和音频控制。尾帧可以单独使用；关键帧能与普通参考混合，各类独立计数：最多 9 张参考图、各 1 张首/尾帧、3 条参考视频、3 条参考音频，以及额外 1 条驱动音频。选择绑定实际素材 ID，不因排序变化改指其他素材；所选素材未进入实际提交集合时会阻止生成。

参考视频每条原素材及偏移后的剩余素材均需为 2–15 秒。起始偏移为非负秒数，随对应的视频内容项发送 `start_time_seconds`，服务按 24 FPS 换算起始帧。已知媒体时长在提交前校验，未知时长还需上游验证。

| audio_control 字段 | 说明 |
| --- | --- |
| mode | `native`、`lock_source`、`remix_source`、`reference_only` |
| denoise_strength | 0–1，0 会保留 |
| add_drive_as_reference | 布尔值，false 会保留 |

有驱动时默认 `lock_source + 0 + true`；没有驱动时默认 `native + 0.35 + false`。非 native 模式要求驱动。`reference_only` 必须有驱动且驱动作为参考，显式 false 会报错；native 也可附带驱动。驱动最长 60 秒，普通参考声音与驱动分开计数。

## 任务与错误

创建使用 `POST /v2/video_generation`，只将 `task_id` 当作任务编号；`request_id` 是追踪编号。查询使用同一 Key 调用 `GET /v2/query/video_generation/{task_id}`，状态为 queued、running、succeeded、failed、cancelled；成功从 `task.content.url` 保存视频，不再通过旧 file_id 检索。

HTTP 错误和 HTTP 200 中的 `task.error` 都会保留失败语义。创建超时、5xx 或无效 JSON 可能已受理，不能自动重发付费任务；错误响应带有效 `X-Task-Id` 时保存并查询已有任务。没有编号时保留不确定状态，需核对原任务，不保证上游编号丢失的任务可恢复。

自定义中转在已有登录态、SSRF 和脱敏边界内携带显式协议身份；系统中转按配置的协议开放创建/查询。密钥不会进入 URL、文档或任务日志。
