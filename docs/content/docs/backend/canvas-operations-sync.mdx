# 画布 operations 同步协议

## 请求合同

画布写入使用 `PATCH /api/canvas-projects/:id/operations`。请求体为：

```json
{
  "mutationId": "客户端生成的稳定请求 ID",
  "baseRevision": 12,
  "operations": [
    {
      "type": "patch_node",
      "id": "node-1",
      "patch": { "metadata.prompt": "新的提示词" },
      "before": { "metadata.prompt": "旧的提示词" }
    }
  ]
}
```

`mutationId` 是重试身份，不是版本号。请求超时、响应丢失、断网、刷新或后台自动重试时，必须使用相同的 `mutationId`、`baseRevision` 和原始 `operations`。修改原始 payload 后复用 ID 会返回 `canvas_mutation_id_reused`。

`baseRevision` 是生成请求时的已确认版本，用于记录和诊断。真正的并发校验在操作本身：字段补丁使用 `before`，对象更新或删除使用 `expected`，顶层字段使用 `beforeValue`。不同字段可以合并；同一字段或同一对象的基线不匹配时返回冲突，节点字段已达到目标值的同值收敛例外见下文。可选顶层字段不存在时，客户端必须在 JSON 中将 `value` 或 `beforeValue` 编码为 `null`，不能让 `undefined` 被序列化为缺失属性。服务端仅兼容早期客户端对这些可选字段省略属性的请求，并按 `null` 参与同样的基线校验。

## 操作类型

- `create_canvas`：只在画布不存在时创建，第一项必须是该操作。
- `create_node`：显式新增节点，已有 ID 不会被覆盖。
- `patch_node`：对已有节点按字段路径更新。节点缺失时失败；字段基线不匹配时，仅当该字段也在 `patch` 中且当前值已等于目标值，才按同值收敛接受（例如 Agent 与浏览器同时回写同一任务的素材、尺寸和终态）。不同目标值仍返回冲突；仅出现在 `before` 中的条件仍严格校验。删除字段的目标 `null` 与字段已不存在等价。请求 ID、摘要核对和事务回执规则不变。
- `remove_node`：按完整对象基线删除节点，并删除关联连接。
- `create_connection`：显式新增连接，两个端点必须存在。
- `update_connection`：按连接对象基线更新，连接缺失或端点缺失都会失败。
- `remove_connection`：按连接对象基线删除。
- `set_field`：更新白名单中的画布字段，并校验 `beforeValue`；字段不存在时用 JSON `null` 表示删除或缺失基线。

只有 create 操作可以创建实体。删除后的迟到编辑、媒体回写或 Agent 更新得到 `canvas_object_missing`，不会隐式重建节点、连接或画布。画布删除后的迟到请求同样不会重建画布；只有新的 `create_canvas` 才能显式重新创建。

## 事务与 receipt

服务端事务按以下顺序处理请求：锁定画布写入、创建或读取 receipt、核对请求摘要、读取当前画布、应用 operations、校验媒体引用、递增 revision、写入画布和完成 receipt。画布内容、revision、receipt 的结果 JSON 在同一事务提交，任一步失败都会回滚。

`canvas_mutation_receipts` 使用 `(user_id, canvas_id, mutation_id)` 唯一约束。相同 ID 和相同摘要返回之前保存的确定性结果，不再次应用操作；相同 ID 和不同摘要返回冲突。receipt 不替代当前画布，也不保存整批版本历史。

结构化容量校验仍在同一事务内使用事务 repository 读取实时用量，但只统计当前账号的素材/画布数量和 JSON 字节数。此路径使用 `UserStructuredStorageUsage`，不扫描任务正文、结果或 API 请求/响应日志；任务与日志配额继续使用原有完整统计。容量上限、创建数量限制、存储锁、CAS 和 receipt 原子提交不变，也不引入可能过期的配额缓存。

## 浏览器 journal 与刷新

浏览器在发送请求前把以下内容写入账号隔离的本地 journal：

- 已确认的画布基线；
- 原始 operations 请求及 mutationId；
- 生成请求时的本地投影；
- 创建时间。

写入响应成功后，浏览器读取服务端完整画布，以原请求的本地投影为基准，将保存期间的新编辑与远端变化三方合并，并同步到实时编辑器。完整画布作为新基线，合并结果持久化后才删除对应未确认请求，避免只推进基线导致下一次保存误删 Agent 新增节点和连线。响应丢失、完整读取失败或合并冲突时保留 journal，重试使用原始请求重放；请求发出后产生的新编辑不会改写原请求，而是在确认后从新基线生成下一批 operations。服务端完整读取或 Agent 刷新不能覆盖仍未确认的本地请求之后的修改。

`viewport` 是本地视图状态，不进入 operations。媒体文件先完成资源登记，再提交引用画布的 operations，避免产生只有节点没有资源记录的远端状态。

打开含未保存编辑的画布时，同样必须合并内容后才能推进基线。有 journal 时保持原基线并等待重放；没有 journal 时复用已确认基线进行三方合并。浏览器重启后若只剩旧远端哈希，则仅当远端 revision 与哈希都匹配时可还原旧基线。无法证明旧基线或同字段冲突时保留本地编辑并报错；直接保存也不能把未核对的脏缓存当作已保存内容。

已确认的完整快照另存于账号隔离的 IndexedDB。每个画布保留新确认快照及当前本地投影对应的上一份基线；轮换前先落盘旧投影，写入成功后才发布新投影。打开、Agent 刷新、增量和保存共用基线恢复：缓存必须同时匹配画布 ID、revision 与内容哈希。写入失败不推进实时画布；账号切换、损坏快照与无法核对的旧版本均不能借此覆盖内容。该缓存不是完整历史，多标签页覆盖或旧客户端从未保存过的基线仍可能无法自动恢复。

助手发送和审批只等待当前画布保存；正在保存其他画布时，当前请求必须继续执行自己的保存，不能把其他批次完成当作当前画布已保存。缺少基线的错误会标明画布名称。旧缓存无可信基线且云端已改变时，反复重试无法还原编辑前状态，需保留本地副本后核对差异。

本地快照与当前云端均不能恢复旧基线时，浏览器使用 `GET /canvas-projects/:id/revisions/:revision` 读取准确版本。服务端先确认用户对现存画布的归属，再读取该版本的完整操作回执。浏览器恢复文本资源后核对 ID、revision 和原内容哈希，全部匹配才执行原有三方合并。缺失版本、摘要型旧回执、损坏回执、哈希不匹配或同字段冲突均保留本地编辑；网络与权限错误原样上报，不降级为强制覆盖。此路径不修改云端画布，不新建生成任务，也不复活已删除画布。

旧客户端可能在节点删除后残留只含 `create_connection` 的悬空连线请求。浏览器先按原 mutationId 重放；只有明确收到 HTTP 400，且整批每条连线都有一个端点在 journal 基线、原请求投影、当前本地画布和最新远端画布中均不存在、远端也没有同 ID 连线、远端版本未倒退时，才通过三方合并移除这些失效本地连线并结束该请求。其他本地编辑保留并另用新 mutationId 提交。混合操作、网络失败、端点恢复或合并冲突仍保留 journal，不自动重建节点，也不放宽服务端端点校验。

## Agent 和媒体回写

普通编辑、Agent、媒体生成终态、预演台、创作提交、LibTV/TapNow 导入都必须经过同一 operations 服务。Agent 事件里的 `canvasPatch` 只是客户端通知：小变更携带有界对象增量；删除、重排、顶层字段变化或事件过大时使用 `requiresRefresh: true`，客户端重新读取后继续处理未确认 journal。

媒体终态只更新仍存在且任务绑定未变化的节点。目标节点已删除、任务绑定已改变或资源不可用时，任务记录保留，画布不创建幽灵节点。
