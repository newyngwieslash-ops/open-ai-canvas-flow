一、可直接执行的任务约束

目标：在真实产品界面的品牌 LOGO/字标位置，将“影策”显示为“源铭振跃”，保证四字名称在登录页、工作区侧栏、管理后台与欢迎页完整可读。默认保留现有图形标识与配色，不设计新图标，不把四字文字塞进小 favicon。

本任务默认是“UI 字标替换”，不是整个项目改名。不得全仓库批量替换“影策”、yingce、open-ai-canvas 或 infinite-canvas。不得修改 LICENSE、NOTICE、第三方署名、协议正文、版权主体、历史记录、用户数据、API 路由、存储 key、插件协议、数据库 schema、包名和部署服务名。不得自动发布、推送或部署。

先检查 git status、根 AGENTS.md、相关目录约定与用户已有变更；不使用 reset --hard、checkout --、清库、清缓存等破坏操作。本方案只完成只读研究，没有修改项目或安装运行依赖。下述代码是实施建议，执行 agent 应在本地真实源码中应用、测试。

默认推荐执行第六节“展示层方案”。理由：当前服务端 brandName 同时决定邮件品牌、协议默认标题和版权页脚，直接改配置或后端默认值会超出纯 UI LOGO 范围。若用户明确要全站品牌重命名，再采用第九节扩展方案，不混用两条路线。

三、源码关键结论

A. 品牌不是散落图片上的两个字
web/src/stores/use-appearance-store.ts：
  DEFAULT_PUBLIC_APPEARANCE.brandName = "影策"
  logoUrl/darkLogoUrl = "/logo.svg"
  seoTitle = "影策"
  brandSlug = "open-ai-canvas"
  brandStudioLabel() 对默认品牌返回 "YINGCE STUDIO"
  applyAppearanceMetadata() 设置 document.title、OG/Twitter metadata 与 favicon

服务端 backend/internal/app/appearance.go 的 defaultAppearanceBrandName 同样为“影策”。系统已有 GET /api/public/appearance 和后台外观设置，已保存配置会覆盖源码默认值。只改前端默认值，在 API 返回原品牌后会改回来；只改后端默认值，有旧配置时也未必生效。

B. 图片标记与文字字标分开
web/src/components/brand/brand-logo.tsx 的 BrandLogo：
  logoConfigured 为 false 时，直接返回调用者 fallback
  已配置自定义 Logo 才加载 appearance.logoUrl/darkLogoUrl
  自定义图加载失败返回中性占位，不能退回旧品牌
web/public/logo.svg 只有 64×64 几何 path，没有“影策”文字。
所以替换 logo.svg 不等于改完所有 logo，也无法替换文字字标。
未配置自定义 logo 时：
  登录页用 /logo.svg 的 CSS mask
  工作区侧栏、管理后台用 lucide InfinityIcon
  欢迎页和加载器使用各自的中性 fallback
这些行为在默认方案中全部保持。

C. welcome 是实际遗漏点
web/src/welcome-application.tsx 只检查 welcomeEnabled，当前未调用 bootstrapAppearance。
web/src/pages/welcome/index.tsx：
  第 62 行 document.title 写死影策
  第 122 行 aria-label 写死影策创作之旅
  首章 h1 读取 chapters[0].title
web/src/pages/welcome/story.ts 第 2 行把该标题写死为影策。
同时欢迎页顶部和底部另从 appearance.brandName 读取品牌。需要统一实际渲染来源，不能只改其中一个。

D. 存在图片内旧品牌
已逐张查看 web/public/welcome/workbench-{canvas,create,project}.webp。
workbench-create.webp 中的侧栏、导航和正文明确包含“影策”像素；源码字符串检索不会发现。
另两张在本次目视检查中未发现同类中文品牌字标。不能据此断言整个仓库所有图片和视频均无旧品牌。

E. 全局改 brandName 的隐含副作用
backend/internal/app/auth_bridge.go 将 appearanceBrandName 传入认证域。
backend/internal/auth/registration.go 会在标题未配置时生成“品牌名服务协议”。
backend/internal/auth/email.go、verification.go、password_reset.go 的邮件身份/内容跟随品牌。
backend/internal/app/appearance.go 的 effectiveAppearanceCopyright 默认由 BrandName 生成版权页脚。
前端多个创作提示、文件导出名、素材库文案也跟随 brandName。
这些不是纯 UI LOGO。本任务不应借改字标重写这些主体信息。

六、推荐实现：前端显示映射，避免业务身份联动

1. 一个轻量纯函数足够
建立 web/src/lib/brand-display.ts，建议：

export const SOURCE_UI_BRAND = "影策";
export const UI_BRAND_NAME = "源铭振跃";

export function displayBrandName(value: string): string {
    return value.trim() === SOURCE_UI_BRAND ? UI_BRAND_NAME : value;
}

export function displayBrandTitle(title: string, brandName: string): string {
    const displayName = displayBrandName(brandName);
    const resolvedTitle = title || brandName;
    return resolvedTitle === SOURCE_UI_BRAND && brandName.trim() === SOURCE_UI_BRAND
        ? displayName
        : resolvedTitle;
}

只把明确的旧默认品牌映射为新字标；保留其他自定义品牌，不正则全局替换管理员设置的标题。自定义 SEO 标题若含原品牌，列为需人工确认，不自动改写。

为什么需要这个文件：多个真实 UI 品牌入口共享同一条“只改变展示、不改变配置/版权/协议”的规则，纯函数消除重复；它不是另造一套品牌配置系统。不要在各组件硬编码四字名称，也不要把整个 appearance 对象的 brandName 重写后放回 store，这会扩散到协议标题等消费者。

2. 各字标组件
原始 appearance 继续保留。在组件内：
  const brandLabel = displayBrandName(appearance.brandName);
只将品牌 LOGO 文字和其可访问名称替换为 brandLabel。
工作区当前已具备 min-w-0、truncate 和图标 shrink-0，先测试四字是否完整，再决定布局改动。
侧栏折叠时当前显示“展开侧栏菜单”按钮，不强行增加文字或改变交互。

3. 登录页英文副标
当前 brandStudioLabel() 对默认值返回 YINGCE STUDIO。默认字标替换时不能让这一旧品牌提示继续与新字标并列。
建议在 auth-scene 局部判断原品牌为 SOURCE_UI_BRAND 时显示中性“AI 创作工作台”，其他自定义品牌继续 brandStudioLabel(appearance)。
不要擅自创造“源铭振跃”的英文品牌名或改 brandSlug；后者关联对象存储建议前缀和诊断身份。

4. 标题与 favicon
在 applyAppearanceMetadata 内计算：
  const name = displayBrandName(appearance.brandName);
  const title = displayBrandTitle(appearance.seoTitle, appearance.brandName);
document.title、og:title、twitter:title 使用 title；og:site_name 使用 name。
seoDescription/keywords 在默认最小范围中保持，作为“可选宣传文案更新”另列；不要碰 footerCopyright。
favicon 继续 appearanceLogoURL，index.html 继续 <title>正在加载</title> 和 data:, 中性占位。不能在首屏 HTML 写死新品牌，以免覆盖自定义部署与破坏已有 bootstrap 测试。
本方案默认包含上述默认页面标题映射；不得改自定义SEO文案。

5. welcome 入口和首章
welcome-application：
  先 getWelcomeAvailability；
  welcomeEnabled !== true 时保持跳转；
  true 时 await bootstrapAppearance() 再渲染 WelcomePage。
该函数已有超时/默认降级，不复制一套 fetch，不让接口失败直接卡死。
注意成功路径会多一个外观请求；验证关闭 welcome 时不额外请求外观，保留当前错误页。

WelcomePage 将 displayBrandName(appearance.brandName) 传入 WelcomeExperience。
将标题单独拆为 useEffect，依赖 [brandName]，设置：
  document.title = `${brandName} · 让一个故事从文字走向银幕`;
避免把品牌依赖塞进原滚动/媒体监听 effect 导致监听反复重装。
section aria-label 改为 `${brandName}创作之旅`。
唯一推荐实现：story.ts 提供纯函数 getWelcomeChapters(brandName)，由保留的六章结构返回首章 title 为传入品牌名的数组；其余五章原样。将固定首章品牌文字从静态模板中移除。WelcomeExperience 使用该函数的返回值渲染 h1 与章节导航，不再直接依赖写死品牌的 chapters。更新此模块调用与测试，不要引入 store 到静态 story 数据模块。
同步原 welcome-story.test.ts 对首章“影策”的断言，改成检测已解析品牌，并保留三个素材版本和全部媒体/署名检查。

6. 实际内容截图
先完成真实 UI，再在本地测试账号/测试数据中截取“创作”页面替换 workbench-create.webp。不要截用户真实邮件、密钥、项目或账号。复用原资源路径可避免无谓改引用，但部署缓存需验证；如采用带版本新文件名，同步 story.ts 的 showcases 对应引用。
测试环境无法运行时保留原图并报告“欢迎页演示截图仍含旧品牌，未完成”；不能涂抹截图或靠隐藏页签掩盖。

七、字体、四字宽度、响应式与可访问性

1. 源码全局字体已含 Inter Variable、PingFang SC、Hiragino Sans GB、Microsoft YaHei 和系统 sans-serif；中文由系统中文字体承担。无需新增网络字体或字体包。保持现有字重与主题 token
2. 侧栏实际最终规则 .app-user-workspace .app-workspace-brand-wordmark 为 15px / 700 / letter-spacing:-.03em。四字约 60px 字宽，通常可容纳，但必须加上图标、间距、内边距、折叠按钮实际测量；不能只凭估计判通过
3. 登录页品牌链接与“播放品牌影片”同排。320/360px 宽时若拥挤，给 logo shrink-0、字标 nowrap，适当缩小局部 gap 或让右侧按钮在窄屏只保留图标并补 aria-label；不要把字标压成单字换行
4. welcome h1 原字号移动端可达 74px、较窄端 66px；四字比原两字宽一倍。优先局部加：
   .welcome-opening h1 { white-space: nowrap; font-size: min(var(--welcome-display), 18vw); }
   这是初始建议，需按实际 --welcome-gutter 和最长自定义名称验证调整，不把此规则套到其他章节。当前只要求四字全显；将该新增nowrap/字号规则用专用class限定于新四字品牌，其他自定义品牌保留原规则，避免影响长名称
5. welcome 顶栏已有 nowrap、移动端15px和22px图标；检查 CTA、菜单按钮与品牌不重叠
6. 管理后台检查展开状态文字、版本号和折叠后工具提示；不为了四字永久加宽整个应用布局
7. 文字是真实 DOM，不改成含字体依赖的 SVG <text> 或四字 PNG。链接以完整“源铭振跃首页”作为 accessible name；装饰图保持 alt=""，避免读屏重复朗读
8. 测试浅色/深色、200% zoom、macOS/Windows 中文字体回退、reduced-motion。现有 focus-visible、动画降级和 logo 失败占位不得破坏
9. 未提供新图形时 favicon 保持原图。将来要新图形：用清晰的方形矢量 mark，分别考虑浅深主题，不能以16px显示四字全文。需同步配置上传、fallback、CSS mask和favicon链路，单改logo.svg不够
